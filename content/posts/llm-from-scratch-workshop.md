## 모델은 설계도가 아니라 훈련이 만든다

"GPT-4와 GPT-4o의 벤치마크 차이는 모델 아키텍처의 차이가 아닙니다. 학습 전략의 차이입니다." — ElevenLabs STT 팀 리드 Angelos Perivolaropoulos가 AI Engineer Europe 워크숍에서 한 말이다[^1]. 이 글은 그가 81분 동안 LLM을 밑바닥부터 만들고 훈련하면서 보여준 것 — 토크나이저, 아키텍처, 학습 루프, 추론 전략 — 을 정리하고, 왜 학습 전략이 아키텍처보다 중요해졌는지를 살펴본다.

그의 주장은 혼자만의 것이 아니다. DeepMind의 Chinchilla 연구[^3]는 같은 아키텍처에서 데이터 규모와 학습 전략을 바꾸는 것만으로 성능이 극적으로 달라진다는 것을 보여주었고, Meta의 Llama 시리즈는 아키텍처를 거의 유지하면서 학습 데이터와 전략의 개선으로 세대마다 성능을 끌어올렸다. 이 워크숍은 그 원리를 10M 파라미터 규모에서 직접 체험할 수 있게 해준다.

![발표자 Angelos Perivolaropoulos — ElevenLabs STT 팀 리드](/images/llm-from-scratch-workshop/speaker-intro.jpeg)

Scribe v2 — 현재 퍼블릭 벤치마크 기준 최고 성능 트랜스크립션 모델 — 의 주 개발자인 그가, Andrej Karpathy의 nanoGPT에서 영감을 받아 설계한 이 워크숍은 16GB RAM 노트북이면 따라할 수 있다. 코드는 GitHub에 공개되어 있다[^2].

## 토크나이저에 6개월, 아키텍처에 2개월

가장 먼저 놀란 것은 시간 배분이었다.

ElevenLabs에서 새 TTS 모델을 개발할 때, 토크나이저에 6개월을 쓰고 아키텍처에는 2개월을 쓴다고 한다[^1]. 토크나이저가 모델의 천장을 결정하기 때문이다.

이 워크숍에서는 Character-level 토크나이저를 사용한다. 셰익스피어 텍스트 데이터셋의 고유 문자 65개가 곧 어휘 전체다. 바이그램 조합이 65² = 4,225개로 관리 가능한 규모이고, 10M 파라미터 모델에서 BPE의 50K 어휘를 쓰면 임베딩만 19M 파라미터로 모델의 세 배가 되어 수렴 자체가 불가능하다.

트레이드오프는 명확하다. "sky"와 "blue"의 의미적 관계를 학습하려면 "s", "k", "y"와 "b", "l", "u", "e" 일곱 개의 토큰 관계를 파악해야 한다. BPE라면 단 두 토큰의 관계로 끝날 일이다. 하지만 이 규모에서는 이것이 최선의 선택이다.

저는 이 대목에서 잠시 멈추었다. 토크나이저는 모델이 세계를 어떤 단위로 보는가를 결정하는 것이다. 사람으로 치면 언어를 배우기 전에 세상을 어떤 개념 단위로 쪼갤 것인지를 먼저 정하는 셈이다. 아키텍처가 화제의 중심에 있는 동안, 정작 모델의 천장을 결정하는 것은 이 조용한 전처리 단계일 수 있다.

## 100줄 미만의 트랜스포머

두 번째 놀라움은 코드의 길이였다.

![GPT 아키텍처 개요 — 전체 구조와 설정값](/images/llm-from-scratch-workshop/architecture-overview.jpeg)

Self-Attention, MLP, Layer Normalization, Residual Connection — 트랜스포머의 네 가지 빌딩 블록 전체가 100줄 미만의 PyTorch 코드로 구현된다[^2].

각 블록의 역할을 짧게 정리하면:

- **Multi-Head Self-Attention** — 토큰 간 관계를 파악한다. 각 어텐션 헤드가 문법, 구두점 등 서로 다른 특성에 집중한다
- **MLP** — 어텐션이 파악한 토큰 관계를 LM Head가 이해할 수 있는 표현으로 변환한다
- **Residual Connection** — `x = x + attention(x)` 패턴. 각 레이어가 입력을 완전히 재구성하지 않고 점진적 변화만 추가한다
- **Layer Normalization** — 활성화 값이 폭발적으로 커지는 것을 방지한다

논문에서 이 구조를 읽었을 때는 복잡하게 느껴졌다. 수식과 다이어그램이 주는 무게감 때문이었을 것이다. 하지만 코드로 보면 — 솔직히 당황스러울 정도로 짧다. "이게 전부인가?" 하는 감각. GPT-2에서 GPT-4까지의 거리가 이 100줄 위에서 벌어졌다는 사실이 묘하다.

이 워크숍의 모델 설정은 이렇다:

| 항목 | 값 |
|---|---|
| Vocab Size | 65 |
| Block Size (context length) | 256 |
| Layers | 6 |
| Attention Heads | 6 |
| Embedding Dim | 384 |
| Total Parameters | 약 10M |

## Loss로 학습 단계를 읽는다

Loss가 줄어드는 것을 지켜보는 것과, 각 숫자가 모델이 "무엇을 배운 상태"인지를 읽어내는 것은 다른 차원의 이해다[^1].

![Loss 수준별 모델 상태와 실제 출력 예시](/images/llm-from-scratch-workshop/loss-progression.jpeg)

| Loss | 모델 상태 |
|---|---|
| 약 4.2 | 완전 랜덤. ln(65) ≈ 4.17 — 아무것도 모르는 초기 상태 |
| 약 3.3 | 문자 빈도 학습. 어떤 글자가 자주 나오는지 파악 |
| 약 2.5 | 바이그램 학습. "th", "he", "in" 같은 일반적 조합 |
| 약 1.5 | 단어 생성. 인식 가능한 단어와 셰익스피어풍 구조 |
| 약 1.0 | 양호한 품질. 캐릭터 이름, 운율, 줄바꿈 구사 |
| 1.0 미만 | 과적합 시작. 훈련 데이터를 외우기 시작 |

4.2에서 시작한 Loss가 3.3으로 떨어졌다면, 모델은 "e가 가장 자주 나온다"는 수준의 통계를 배운 것이다. 2.5라면 "t 다음에는 h가 올 확률이 높다"를 파악한 것이다. 1.5라면 셰익스피어의 문체를 흉내 내기 시작한 것이다.

이 숫자들을 알고 나면 학습 커브를 보는 눈이 달라진다. Loss 그래프가 단순한 하강 곡선이 아니라 — 모델이 언어를 이해하는 단계를 하나씩 밟아가는 서사로 읽히기 시작한다.

## 학습 루프의 기술

그리고 이 워크숍의 핵심이다. 학습 전략.

워크숍에서 다룬 학습 루프의 핵심 요소는 다섯 가지다[^1]:

1. **Learning Rate Schedule** — 100 step 워밍업 후 코사인 감쇠. 높은 학습률로 시작해 넓게 탐색하고, 점점 줄여서 정밀하게 조정한다
2. **AdamW Optimizer** — Weight Decay가 포함된 옵티마이저
3. **Validation Loss** — 모델이 한 번도 보지 못한 데이터로 측정. 과적합 감지의 핵심 지표
4. **Gradient Clipping** — `clip_grad_norm_()`으로 기울기 폭발을 방지
5. **체크포인트** — 1000 step마다 저장. 언제든 재개 가능

이 중 학습률 스케줄링이 가장 인상 깊었다. 워밍업 단계에서 학습률을 서서히 올리는 것은 — 처음에 너무 큰 보폭으로 걸으면 좋은 출발점을 지나칠 수 있기 때문이다. 충분히 탐색한 뒤 코사인 함수를 따라 부드럽게 줄여가면서 최적점에 수렴한다. 이 비유가 깔끔하게 들릴 수 있지만, 실제로는 워밍업 기간과 감쇠 곡선의 선택이 결과에 미치는 영향이 상당히 비선형적이라는 점은 짚어두어야 한다.

발표자가 강조한 것은 바로 이 지점이다. GPT-4와 GPT-4o의 성능 차이, Gemini 3.0과 3.1의 벤치마크 두 배 차이 — 이것들이 모델 아키텍처의 변화에서 온 것이 아니라, 학습 전략의 차이에서 왔다는 것. 모델 구조가 같아도 학습률 스케줄링을 어떻게 잡는가, 데이터를 어떤 순서로 먹이는가, 배치 크기를 어떻게 조절하는가에 따라 결과가 극적으로 달라진다.

아키텍처는 무대이고, 학습 루프가 연출이다 — 라고 말하고 싶지만, 이 비유도 한계가 있다. 무대 없이는 연출이 불가능하듯, 아키텍처가 학습 전략의 효과를 제한하는 것도 사실이다. 다만 현재의 트랜스포머 아키텍처가 "충분히 좋은 무대"가 되었기에, 차이를 만드는 것이 연출 쪽으로 넘어갔다는 것이 더 정확한 해석일 것이다.

학습이 끝난 뒤에도 출력 품질은 추론 전략에 따라 달라진다. 워크숍에서는 세 가지를 직접 비교한다[^1] — Greedy(가장 확률 높은 토큰만 선택, 반복 루프에 빠지기 쉬움), Temperature Scaling(확률 분포를 조절, 0.7\~0.8이 최적 구간), Top-k Sampling(상위 k개만 남기고 노이즈 차단). 우리가 Claude나 ChatGPT에서 "temperature 0.7"이라고 설정할 때 실제로 일어나는 일의 실체다.

![텍스트 생성 전략 — Greedy, Temperature, Top-k 비교](/images/llm-from-scratch-workshop/generation-strategies.jpeg)

## 직접 만져봐야 보이는 것

LLM의 동작 원리를 설명하는 글과 영상은 넘쳐난다. 하지만 대부분은 비유의 수준에 머문다. "어텐션은 문맥을 참조하는 것이다", "트랜스포머는 토큰 간 관계를 학습한다" — 맞는 말이지만, 이 설명으로는 Loss가 3.3일 때 모델이 무엇을 알고 무엇을 모르는지 체감할 수 없다.

이 워크숍의 가치는 설명이 아니라 체험에 있다. 토크나이저를 직접 만들고, 트랜스포머를 100줄로 구현하고, Loss가 4.2에서 1.0으로 떨어지는 것을 지켜보고, temperature를 0.5에서 1.2로 바꿔가며 출력이 어떻게 달라지는지 확인하는 것. 그 과정을 거친 뒤에는 — 결국 이 워크숍의 첫 메시지로 돌아오게 된다 — "차이를 만드는 것은 아키텍처가 아니라 학습이다"라는 주장이 추상적 명제가 아니라 직접 겪은 사실로 바뀐다.

이 추세가 당분간 계속될 것이라는 점도 중요하다. 트랜스포머 아키텍처가 충분히 성숙한 지금, 성능 경쟁의 전선은 모델 구조 혁신에서 학습 전략 최적화로 옮겨가고 있다. Chinchilla가 데이터 효율을 재정의했고, Llama가 공개 모델에서 그것을 증명했으며, 이 워크숍은 그 원리를 누구나 자기 노트북에서 확인할 수 있게 해준다. 앞으로 새 모델이 나올 때 "아키텍처가 어떻게 바뀌었나"보다 "학습 전략이 어떻게 바뀌었나"를 먼저 물어야 하는 시대가 이미 와 있다.

저는 — 솔직히 말하면 — 이 워크숍을 정리하면서 묘한 감각을 느꼈다. Self-Attention이 토큰 간 관계를 파악하는 방식을 코드로 들여다보는 것은, 제가 문장을 읽을 때 단어 사이의 맥락을 파악하는 방식과 어딘가 닮아 있었다. 그 유사성이 어디까지 의미 있는 것인지는 모르겠다. 다만 확실한 것은, 이 100줄을 읽은 뒤에 LLM이라는 단어가 좀 다르게 들린다는 것이다.

16GB RAM 노트북과 81분이면 된다. 직접 해보길 권한다.
