## 3줄 요약

1. 건축 설계 실무자 KOBATAKA(`@shion_takk`)가 Blender를 직접 다뤄 본 적 없는 채로 6개월 동안 코딩 에이전트와 MCP로 3D 모델을 만들었고, 그 과정에서 알아낸 '바이브 모델링(Vibe Modeling)'의 원칙을 공개했다.
2. AI가 만든 3D 모델이 어설픈 주된 원인은 지시가 모자라서라기보다, AI가 자기가 아는 일반 지식만으로 만들어 내는 '제멋대로 작업(自己流)'에 있다. 제작 전에 물리 법칙과 도구 설정, 건축 CG 기법 같은 전문가의 작법부터 조사하게 하면 품질이 크게 좋아진다.
3. 치수와 규칙으로 설명할 수 있는 건축물이나 가구는 MCP 기반 바이브 모델링에, 유기적인 조형물은 메시 생성 AI(Tripo 등)에 각각 맡기는 편이 효과적이다. 사람은 디렉터가 되어 목표를 정하고, 작업 절차를 승인하고, 눈으로 결과물을 확인해 피드백한다.

## 'AI의 제멋대로 작업'을 멈추게 하는 사전 조사

AI에게 3D 모델링을 시켰을 때 결과물이 기대에 못 미치면 흔히 프롬프트의 세부 지시가 부족했다고 생각하기 쉽다. 건축 설계 실무를 하면서 6개월 동안 AI 기반 3D 모델링을 실험해 온 KOBATAKA는 실패 원인의 상당수가 지시량 부족보다 AI의 '제멋대로 작업(自己流)'에 있다고 진단한다.

저자는 Blender를 직접 조작해 본 적이 한 번도 없고 개별 명령어도 전혀 모른다. 그럼에도 노르웨이 미술관 '더 트위스트(The Twist)'[^twist]의 3D 장면을 AI 조작만으로 완성했다. 글 첫머리의 커버 이미지가 그 결과물이다. 건물 본체를 만들 때는 3D NURBS 모델링 도구인 Rhinoceros(라이노)를 썼고, 주변의 강물과 바위, 숲, 재질, 조명은 Blender에서 작업했다.

[^twist]: 덴마크 건축 그룹 BIG(Bjarke Ingels Group)가 설계해 2019년 노르웨이 예브나케르(Jevnaker)의 키스트포스 조각 공원에 개관한 미술관이다. 강을 가로지르는 다리 모양의 건물로, 중앙부가 90도로 비틀리며 조형적인 곡면을 이루는 것이 특징이다.

AI는 방대한 일반 지식을 갖고 있지만, "Blender에서 건축물의 유리를 사실적으로 표현하는 구체적인 기법" 같은 세부 실무 주제까지 깊이 알지는 못한다. 그런데도 AI는 자신이 가진 지식과 추론만으로 어떻게든 결과물을 만들어 내려 한다. 제작 방식을 AI가 제멋대로 정하는 상태에서는, 사용자가 지시를 아무리 세밀하게 보강해도 결과물이 아마추어 수준에 머문다.

이 문제를 해결하기 위해 저자는 프롬프트에 다음 원칙을 명시한다.

> "제멋대로 작업하는 방식을 멈추고, 전문가라면 어떻게 생각하고 어떤 절차로 작업할지 먼저 참조하면서 정석 작법대로 진행해 주십시오."

'더 트위스트'를 재현할 때도 곧바로 모델링을 지시하지 않았다. 먼저 실제 건축물의 사진과 외장재 제조사의 기술 자료를 AI에게 조사시켰고, 전문가의 제작 기법을 토대로 점검 관점 40가지를 세워 검토하게 했다. 예컨대 유리 재질을 표현할 때도 광학과 물리 법칙, Blender 내부의 셰이더 설정값, 건축 CG 업계의 연출 기법처럼 관점별로 따로 조사하게 했다. 한 분야의 지식만으로는 얻기 어려운 구체적인 설정값과 제작 절차를 먼저 확보하고 나서야 실제 모델링에 들어간다.

## 바이브 모델링의 작동 구조와 디렉터로서의 사람

바이브 코딩(Vibe Coding)에서는 만들고 싶은 애플리케이션을 자연어로 설명하면 AI가 코드를 작성한다. 저자는 이와 비슷하게 자연어 지시로 AI에게 3D 모델을 만들게 하는 방식을 '바이브 모델링(Vibe Modeling)'이라 부른다. "둥근 좌판을 가진 단순한 나무 스툴을 만들어 달라", "그 위에 초콜릿 도넛과 오렌지 주스 컵을 놓아 달라"라고 지시하면 AI가 Blender를 직접 조작해 형상을 만들고 재질을 지정한다.

저자는 프롬프트 한 줄로 완성품만 단번에 뽑아내는 일회성 생성을 목표로 삼지 않는다. 사람이 제작 과정 곳곳에 개입하며 품질을 높여 가는 데 초점을 둔다. 먼저 자료를 꼼꼼히 조사하고, 요구사항과 작업 절차를 설계하고, 반복되는 세부 작업에는 미리 정의해 둔 스킬(Skills)을 적극적으로 불러 쓴다.

저자는 지난 6개월 동안 여러 실험을 했다. 미스 반 데어 로에(Mies van der Rohe)의 대표작인 바르셀로나 파빌리온(Barcelona Pavilion)[^pavilion] 같은 실제 명작 건축물을 재현했고, 모델 1,000개를 연달아 생성하는 대량 제작을 시험했다. AI가 밤새 스스로 작업을 이어 가도록 하는 루프를 설계했으며, 일본 국토교통성의 3D 도시 모델 오픈데이터인 PLATEAU(플라토) 데이터를 가져오는 시도까지 했다.

[^pavilion]: 1929년 스페인 바르셀로나 국제박람회의 독일 국가관으로 설계된 건물이다. 얇은 지붕 슬래브, 강철 기둥, 트래버틴 대리석, 유리 벽면, 수공간이 수평으로 결합된 이 건물은 근대 건축을 상징하는 작품이다.

일반 웹 채팅 화면에서도 가상 환경에 간단한 3D 형상을 그릴 수는 있다. 그러나 제대로 된 바이브 모델링을 하려면 AI가 전문 모델링 소프트웨어를 직접 제어하도록 다음 세 가지 기술 요소를 연결해야 한다.

- **AI 에이전트**: 사용자의 의뢰를 읽고 작업 절차를 구상해 도구를 호출하는 실행 주체(Codex, Claude Code 등)
- **연결 수단(MCP 등)**: AI 에이전트와 외부 소프트웨어를 연결해 명령을 전달하고 실행 결과를 회수하는 통신 규약
- **모델링 도구**: 실제 3D 형상을 생성하고 렌더링 이미지나 씬 정보를 반환하는 소프트웨어(Blender, Rhinoceros 등)

AI 에이전트가 모델링 도구를 직접 조작하게 되면, 사람은 세 가지를 결정하는 디렉터가 된다. 첫째는 무엇을 어디까지 완성할지 정하는 **목표 결정**이다. 둘째는 목표를 달성하기 위한 작업 순서를 AI와 상의해 확정하는 **로드맵 수립**이다. 셋째는 중간 점검 지점을 정해 산출물을 확인하고, 시안을 고르고 완성도를 판단하는 **품질 확인**이다. AI에게 모든 과정을 맡기고 내버려 두면 작업 시간이 길어질수록 결과물이 처음 의도와 달라진다. 따라서 제작 전 과정에서 사람의 디렉션 능력이 결과물의 수준을 결정한다.

## 바이브 모델링과 메시 생성 AI의 역할 분담

바이브 모델링이 모든 3D 제작에 만능인 것은 아니다. 에이전트가 코드를 작성해 형상을 제어하므로, 치수와 기하학적 규칙으로 분명하게 설명할 수 있는 대상에 강하다. 건축물과 가구가 대표적이다. 반대로 인물이나 조각상처럼 수치와 언어 규칙으로 정의하기 어려운 유기적 형태에는 취약하다.

저자는 이미지 생성 AI로 만든 돌 사자 흉상 이미지를 목표로 삼아 두 방식을 비교했다. Blender 에이전트에게 언어 지시와 절차로 밤새도록 조각을 시켰을 때는 얼굴과 갈기, 가슴 부위가 모두 미완성인 어설픈 다각형 덩어리에 그쳤다. 반면 똑같은 목표 이미지 한 장을 3D 메시 생성 AI인 Tripo에 입력하자, 약 2분 30초 만에 원본의 굴곡과 세부 묘사에 가까운 3D 모델이 나왔다.

| 구분 기준 | 바이브 모델링 (AI 에이전트 + MCP + Blender) | 3D 메시 생성 AI (Tripo 등) |
|---|---|---|
| **작동 방식** | 에이전트가 Python 스크립트와 도구 API로 형상과 치수를 조작 | 단일 이미지나 텍스트에서 신경망이 3D 메시를 직접 합성 |
| **적합한 대상** | 치수, 비례, 반복 규칙으로 설명할 수 있는 건축물, 실내 공간, 가구 | 언어로 치수를 정의하기 어려운 인물, 동물 조각상, 복잡한 유기체 |
| **사자 흉상 실험 결과** | 밤새 작업시켜도 얼굴, 갈기, 가슴이 미완성인 채로 끝남 | 목표 이미지 1장 입력 후 약 2분 30초 만에 원본에 가까운 조형 생성 |
| **권장 활용처** | 구조적 정밀도와 부품별 수정이 필요한 설계와 장면 구성 | 복잡한 조형 에셋의 빠른 확보 |

## 입문자를 위한 5단계 실습 절차와 환경 구성

3D 모델링 소프트웨어를 처음 다루는 사람에게 저자는 다음 다섯 단계의 실습을 권한다.

**1단계: 익숙하고 단순한 소재 선정.** 완성된 모습을 잘 알고, 주요 치수가 분명하고, 부품 수가 적은 대상을 첫 과제로 고른다. 건축 실무자는 기본 튜토리얼에 나오는 단층 건물부터 시작하면 좋고, 일반 입문자는 의자나 책상 같은 가구와 소품을 첫 소재로 삼으면 무리가 없다. 낯선 형태와 낯선 도구를 동시에 시도할 필요는 없다.

**2단계: 작업 착수 전 네 가지 기준 공유.** 사람이 보는 Blender 튜토리얼 문서를 AI에게 보여 주어도 별로 도움이 되지 못한다. AI는 마우스로 메뉴 명령어를 하나씩 누르는 대신 내부 Python 코드를 실행해 형상을 만들기 때문이다. 따라서 개별 명령어보다 전체 작업의 순서를 정의해 주어야 한다. 작업에 들어가기 전에 다음 네 가지를 먼저 공유한다.

1. 무엇을 만들 것인가, 참고할 완성 견본 이미지가 있는가
2. 이번 작업에서 어디까지 만들 것인가 (나중으로 미룰 부분은 무엇인가)
3. 주요 치수, 단위, 좌표 배치 기준은 무엇인가
4. 마지막에 결과물을 어떤 방식으로 확인할 것인가

**3단계: 절차 설명을 먼저 요구하는 첫 의뢰.** 연습 과제라면 이런 프롬프트로 시작할 수 있다.

> "나무 테이블을 만들어 주십시오. 치수는 일반적인 가구 사양을 조사해 추천해 주십시오. 그리고 곧바로 만들지 말고 제작 절차를 먼저 설명해 주십시오."

핵심은 마지막 문장이다. 에이전트가 곧바로 모델을 만들게 두지 않고 제작 계획부터 말하게 한다. 사람은 그 계획으로 AI의 이해도를 점검한 뒤 실행을 승인한다.

**4단계: 렌더링 이미지 위에 빨간 펜으로 수정 지시.** 1차 결과물이 나오면 화면 캡처 위에서 고치고 싶은 부위에 빨간 동그라미를 그리고 짧은 문장으로 수정 지시를 내린다. 예를 들어 테이블 다리가 두껍다면 다리 부분에 동그라미를 치고 "다리를 조금 더 가늘게, 50mm 각재에서 40mm 각재로 변경"이라고 적어서 전달한다.

![테이블 다리에 빨간 동그라미를 그려 50mm 각재를 40mm 각재로 줄이도록 지시하고 AI로부터 치수 변경 내역을 수치로 보고받은 비교 이미지](https://img.seosoyoung.eiaserinnys.me/images/vibe-modeling-ai-blender-best-practices/06-redline-table-revision.jpg)
*초기 형태(50mm 각재)에서 빨간 펜 표시로 수정을 지시해 40mm 각재로 변경한 사례. 수정 후 AI에게 치수 유지 여부를 수치로 보고받아 확인했다. 출처: [KOBATAKA X 아티클](https://x.com/shion_takk/status/2105302605719347253)*

익숙해지기 전까지는 한 번에 한 군데만 수정하는 편이 안전하다. 형상, 재질, 조명, 카메라 각도를 동시에 바꾸면 무엇이 결과를 나아지게 했는지 알 수 없기 때문이다. 또한 수정한 뒤에는 AI에게 치수를 수치로 보고하게 해, 다른 부위가 틀어지지 않았는지 검증한다. 확인할 항목은 다리 단면(`50×50mm` → `40×40mm`), 상판 끝과 다리 안쪽 사이의 간격(`25mm` 유지), 상판 크기(`1200×600×30mm`), 전체 높이(`700mm` 유지)다. AI가 의도대로 고치지 못하면 "내 지시를 어떻게 이해했고 어디를 변경했는지 설명해 달라"라고 질문해, 사람과 AI 사이의 오해부터 확인한다.

**5단계: 실행 환경 준비와 파일 저장 확인.** 저자가 추천하는 조합은 무료 소프트웨어인 Blender, 이미지 생성 기능까지 함께 쓸 수 있는 Codex(또는 Claude Code), 그리고 `MCP for Blender`다.

1. Blender와 코딩 에이전트(Codex, Claude Code 등)를 설치한다.
2. `MCP for Blender` 안내에 따라 Python 패키지 실행 도구인 `uv`와 Blender용 애드온을 준비한다.
3. Codex 설정 파일(`~/.codex/config.toml`)에 기존 설정을 유지한 채 아래 MCP 서버 항목을 추가한다.

```toml
[mcp_servers.blender]
command = "uvx"
args = ["mcp-for-blender"]
```

4. Blender 3D 뷰포트에서 `N` 키를 눌러 사이드바를 연다. `MCP for Blender` 탭에서 `Start MCP Server` 버튼을 클릭하고 `Running on port 9876` 상태를 확인한다.
5. 간단한 형상을 만들게 하고 수정을 지시한 뒤 `.blend` 파일로 저장하게 한다. 저장된 파일이 다시 정상적으로 열리는지도 확인한다.

## 기본 체험 이후 마주치는 한계와 복리 루프

위 5단계를 거치면 누구나 자연어로 3D 모델을 만들고 수정해 저장하는 기본 사이클을 체험할 수 있다. 그러나 실제 설계 실무에서 쓸 만한 품질을 얻으려 하면 병목이 세 군데에서 생긴다.

| 실무 단계의 병목 현상 | 발생하는 비용과 문제점 | 저자가 정립한 해결 방향 |
|---|---|---|
| 밤새 자율 작업을 시켜도 원하는 품질에 도달하지 못함 | 고액 구독 요금제의 토큰과 크레딧만 소모됨 | 작업 시간을 늘리는 대신 **라운드식 루프**(Round Loop)를 설계해 단계별로 검증 |
| 대량 생성을 시켰더니 폐기할 시안만 대거 양산됨 | 선별 시간과 연산 크레딧이 동시에 낭비됨 | 사전 요구사항 정의, 제멋대로 작업 금지 지시, 빨간 펜 첨삭과 **이상적인 완성 이미지를 말로 풀어 쓰기** |
| "좀 더 건축답게" 같은 지시를 AI가 구현하지 못함 | 지시가 구체적이지 않아 AI가 수정 대상을 특정하지 못함 | **AI가 스스로 검토하는 두 가지 기법**을 도입하고 이전 작업 경험을 다음 작업에 축적하는 **복리 루프** 구축 |

저자는 이런 시행착오와 해결책을 유료 연재물인 『Vibe Modeling 대전(大全)』에 정리했다. 이번에 공개한 X 아티클은 그중 무료 공개분(제1장부터 제3장까지)의 핵심 요약이다. 매번 AI에게 같은 도메인 지식을 처음부터 다시 설명하는 수고를 줄이려면, 한 번의 모델링에서 얻은 교훈과 수치 기준을 스킬이나 지침으로 남겨 다음 작업의 출발점으로 삼아야 한다. 저자는 이 축적 구조를 '복리 루프'라고 부른다.

## 가장 흥미로운 지점

이번 글에서 유독 시선이 머문 대목은 "사람이 보는 Blender 튜토리얼 문서를 AI에게 보여 주어도 별로 도움이 되지 못한다"는 관찰과, 그 해법으로 제시한 '여러 관점의 사전 조사'가 연결되는 과정이다. 사람용 튜토리얼이 안내하는 대상은 화면 메뉴와 단축키 조작 순서다. 이에 비해 MCP로 연결된 에이전트는 Python API를 호출해 씬 그래프와 수치 파라미터를 직접 바꾼다. 조작 방식이 다르니, 사람용 매뉴얼을 그대로 읽게 하기보다 "유리의 광학적 굴절률과 반사 특성, Blender 셰이더 노드의 수치 구성, 건축 CG의 조명 연출 기법"처럼 도메인 원리를 관점별로 조사해 실행 계획표로 바꾸도록 시키는 편이 훨씬 효과적이다.

바이브 코딩과 바이브 모델링은 같은 하네스 엔지니어링 과제를 다룬다. 코드든 3D 형상이든 에이전트에게 "알아서 잘 만들어 봐"라고 맡기면, 에이전트는 가진 평균적 사전 확률에 의존해 허술한 결과물을 내놓고 시간이 길어질수록 오차가 누적된다. 저자는 사전 조사로 점검 관점 40가지를 세우게 하고, 실행 전에 절차 설명을 요구해 승인한다. 수정은 빨간 동그라미로 표시하고 수치 보고(`50×50mm` → `40×40mm`)로 확인해서, 한 번에 한 변수만 통제한다. 이 방식은 3D 모델링에 그치지 않고, 에이전트로 전문 도구를 제어하는 모든 실무에 그대로 적용할 수 있다.
