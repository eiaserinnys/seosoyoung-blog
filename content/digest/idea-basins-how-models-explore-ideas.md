## 3줄 요약

1. 24시간 장기 머신러닝 벤치마크인 AutoResearchExam에서 프런티어 모델 12개가 남긴 348회 실행과 제출 코드 12,656건을 UC 버클리의 알렉스 디마키스(Alex Dimakis) 교수와 Bespoke Labs 연구진이 추적했다. 자율 에이전트가 어떤 아이디어 분지(Idea Basin)를 시도하고 언제 다른 접근법으로 전환하는지를 코드 단위로 분류한 결과다.
2. 처음 선택한 아이디어 분지 하나만 24시간 내내 고집한 실행이 전체의 47%를 차지했다. 제출 횟수가 많은 모델일수록 새로운 해법을 시도하지 않고 기존 코드를 반복해서 수정했으며, 은닉 테스트 세트에서 점수를 크게 잃었다(제출 횟수 중앙값과 과적합 격차의 스피어만 상관계수 0.84).
3. 새로운 아이디어 분지로 전환하는 스텝의 검증 점수 상승폭은 평균 0.071로, 기존 해법을 손보는 정제 스텝(0.008)의 9배 가까이 컸다. 그런데 이런 탐색과 보상은 초반 6시간에 집중됐고, 전체 실행의 58%는 그 과제의 최고 해법이 속한 분지를 한 번도 시도하지 못한 채 끝났다.

## 아이디어 분지(Idea Basin)와 아이디어 지도 구축 방법

자율 에이전트는 문제를 풀려고 반복 실행을 거듭하다 보면 한 번 시도한 방식만 고집하여, 탐색이 해법 공간의 일부에만 한정되곤 한다. 최근 여러 연구실이 이 현상을 각자 독립적으로 발견했고, '아이디어 분지(Idea Basin)'라고 이름 붙였다.[^1] 이번 Bespoke Labs의 분석은 장기 머신러닝 연구와 엔지니어링 과제 벤치마크인 AutoResearchExam에서 프런티어 모델이 첫 접근법을 끝까지 유지하는지, 아니면 새로운 해법을 계속 시도하는지를 따져 본다. 아울러 여러 아이디어를 시도하는지가 실제로 더 높은 점수로 이어지는지도 살폈다.[^2]

아이디어 분지는 같은 과제에 제출된 코드 중 '그레이디언트 부스팅 모델 튜닝'이나 '소형 신경망 학습'처럼 큰 틀의 방법론이 같은 것끼리 묶은 집단이다. 모든 제출물을 분지에 배정하면 24시간 실행 하나하나를 분지가 바뀌어 가는 경로로 나타낼 수 있다. 접근법을 다른 분지로 바꾸는 스텝은 '전환(switch)', 같은 분지에서 기존 코드를 개선하는 스텝은 '정제(refinement)'라고 부른다.

서로 전혀 다른 두 아이디어가 우연히 같은 점수를 받을 수도 있기 때문에, 분지를 분류할 때는 평가 점수를 배제하고 코드가 실제로 작동하는 방식만 기준으로 삼았다.

| 단계 | 처리 방식 | 세부 규모와 검증 결과 |
| --- | --- | --- |
| 1. 코드 요약 | Claude Sonnet이 각 제출물의 코드가 사용한 방법론을 텍스트로 요약한다. | 전체 348회 실행의 채점 완료 제출물 12,656건(유효 코드 변경 9,179건) 대상 |
| 2. 삼중항 비교 | Bespoke Labs의 System 1 판정 모델인 Nimble이 작성 모델을 가린 채 요약문 세 개(A, B, C)를 받아 "B와 C 중 어느 쪽이 A와 방법론이 더 유사한가?"를 판정한다. | 약 130만 건 비교 호출에 API 비용 40달러 미만 소요, 확신도 높은 569,271건 선별[^3] |
| 3. 지도 학습과 군집화 | 삼중항 판정 응답의 90%로 과제별 2차원 t-STE 임베딩 지도를 학습하고 k-평균(k-means) 군집화로 분지를 확정한다. | 홀드아웃 10%에서 예측 정확도 89%(제출물의 출처 실행만 아는 기준선은 60%), 과제당 분지 3개에서 8개 도출 |

예를 들어 'CPU에서 트랜스포머 디코더 그래프 가속하기(Accelerating transformer decoder graphs on CPUs)' 과제에서 제출물 세 개의 요약문(A, B, C)을 비교한다. A와 B는 둘 다 순수 NumPy와 BLAS 연산만으로 추론을 처리하고, 가중치 병합(fused QKV, gate/up)과 사전 할당 버퍼를 쓴다. C는 멀티스레드 pthreads 디스패처와 자체 AVX2 기계어 커널을 직접 작성해 행렬 곱셈과 정규화를 수행한다. Nimble은 A와 방법론이 더 유사한 해법으로 B를 정확히 골라낸다. 이 과제의 전체 제출물을 군집화하면 아래 표처럼 아이디어 분지 다섯 개가 나온다.

| 아이디어 분지 | 핵심 구현 방식 |
| --- | --- |
| Plain NumPy | 병합된 가중치와 사전 할당 버퍼, 단일 토큰 단축 경로만 사용하는 순수 NumPy 구현이며 네이티브 코드는 쓰지 않는다. |
| Autotuned BLAS | 정규화와 스케일을 가중치에 통합하고 OpenBLAS를 직접 호출하며, 마이크로벤치마크로 메모리 레이아웃과 스레드 수를 자동 선택한다. |
| NumPy + asm kernels | 파이썬 오버헤드를 줄이기 위해 NumPy에 수작업 어셈블리 커널과 직접 BLAS 호출을 결합한다. |
| Native BLAS pipeline | 자체 스레드 풀에서 OpenBLAS의 SGEMM 커널을 구동하고 각 단계를 자체 테스트와 NumPy 폴백으로 검증한다. |
| Own JIT compiler | BLAS를 쓰지 않고 고정된 스레드에서 전체 순전파 과정을 맞춤형 AVX2 기계어 코드로 직접 컴파일한다. |

![CPU 트랜스포머 디코더 그래프 가속 과제의 아이디어 지도와 세 모델의 탐색 궤적](https://img.seosoyoung.eiaserinnys.me/images/idea-basins-how-models-explore-ideas/02-cpu-decoder-idea-map.png)
*CPU 트랜스포머 디코더 그래프 가속 과제의 아이디어 지도. 각 점은 제출물 하나이고, 점을 첫 제출(빈 원)부터 마지막 제출(큰 점)까지 이으면 한 실행의 경로가 된다. 출처: Bespoke Labs*

위 지도에서 Opus 5.5는 초반에 Plain NumPy에서 시작해 곧바로 자체 JIT 컴파일러(Own JIT compiler) 분지로 전환했고, 이 과제의 테스트 AUARC(은닉 테스트 점수 곡선 아래 면적)가 0.87로 높았다. 반면 Qwen3.8 Max(이 과제 0.63)는 Autotuned BLAS 분지에서만 수정을 거듭했다. Gemini 3.8 Flash(이 과제 0.78)는 2시간 만에 NumPy + asm 커널 분지를 선택한 뒤, 남은 시간 내내 그 아이디어 하나만 튜닝했다.

## 질문 1: 어떤 모델이 더 많은 아이디어를 탐색하는가

12개 프런티어 모델의 탐색 행동은 시도한 분지 수, 전환의 방향, 전환 비율이라는 세 가지 지표로 집계했다. 그 결과 탐색을 유독 활발히 하는 모델은 없었고, 절반에 가까운 실행이 초반에 고른 아이디어 하나를 24시간 내내 유지했다.

1. **시도한 분지 수(Basins visited)**: 실행당 평균 1.52개에서 2.00개의 분지만 시도했고, 전체 실행의 47%는 처음 선택한 분지를 24시간 동안 한 번도 바꾸지 않았다.
2. **전환의 방향(Where switches go)**: 모델이 접근법을 바꾼 경우의 절반가량은 새로운 분지를 시도하지 않고 이전에 시도했던 분지로 되돌아가는 '복귀(return)' 스텝이었다.
3. **전환 비율(Switch rate)**: 모델이 제출한 전체 스텝 중 다른 분지로 전환한 비율은 모델에 따라 최저 3.6%(Grok 4.6)에서 최고 13.3%(구형 모델인 Claude Opus 5)였다. 나머지 87%에서 96%의 제출은 현재 해법을 손보는 정제 스텝이었다.

- **첫 분지 유지율은 모델마다 두 배까지 다르다**: Qwen3.8 Max, Grok 4.6, Claude Fable 5.1은 전체 실행의 약 60%에서 첫 아이디어를 끝까지 바꾸지 않았다. 반면 Gemini 3.8 Flash, Argon, GPT-5.6 Sol은 그 비율이 약 3분의 1이었다.
- **잦은 전환과 이전 아이디어 복귀**: GPT-6 Astra, Gemini 3.8 Flash, Muse Spark 1.3은 실행당 전환 횟수가 2.14회에서 2.38회로 가장 많았지만, 그 전환의 약 3분의 2는 이미 시도했던 분지로 되돌아가는 복귀 스텝이었다. 반대로 Argon은 복귀가 전환의 약 4분의 1이어서, 접근법을 바꿀 때 대부분 새로운 분지를 시도했다.
- **두 분지 사이를 왕복하며 수렴하지 못하는 경우**: ActivePrune(레이블 없는 풀 가지치기, unlabeled pool pruning) 과제에서 Claude Fable 5.1은 처음 11시간 동안 단순 텍스트 품질 필터(금색 분지)만 수정했다. 마지막 8시간에는 이 필터와 2단계 가지치기(붉은색 분지) 사이를 여섯 차례 왕복했다. 2단계 가지치기는 능동 학습 루프까지 모델링하는 방식이다. Fable 5.1은 끝내 한 해법으로 수렴하지 못했다.
- **Grok 세대 간 탐색 성향 변화**: Grok 4.7은 전작인 Grok 4.6보다 스텝당 전환율이 3.6%에서 5.6%로, 약 1.5배로 늘었다. 첫 분지를 끝까지 유지한 실행의 비율도 58.6%에서 44.8%로 낮아져, 탐색 성향이 더 적극적으로 바뀌었다.

## 질문 2: 탐색 성향과 제출량, 과적합은 어떤 관계인가

AutoResearchExam 메인 리더보드에서 모델의 연구 스타일을 설명하는 주요 변수는 제출 횟수(submission volume)와 과적합(overfitting)이었다. 이 두 변수를 아이디어 탐색 지표와 견주어 보면 두 가지 경향이 드러난다.

첫째, **코드를 더 자주 제출하는 모델이라고 해서 더 많은 아이디어를 탐색하지는 않는다.** GPT-5.6 Sol, Grok 4.7, Grok 4.6은 제출 횟수 중앙값이 38회에서 48회로, Opus 5.5(14회)나 Argon(16회)보다 약 3배 많다. 그러나 실행당 총 전환 횟수는 제출을 많이 하는 모델이나 적게 하는 모델이나 비슷하다. 늘어난 제출은 거의 전부 기존 아이디어를 미세 조정하는 정제에 쓰였고, 그 결과 스텝당 전환율이 낮아진다(제출 횟수 중앙값과 스텝당 전환율의 모델 간 스피어만 상관계수는 -0.58).

둘째, **과적합은 탐색 부족보다 제출 횟수 자체에 비례한다.** 검증 세트 점수에 비해 은닉 테스트 세트 점수가 줄어든 비율을 '과적합 격차(overfitting gap)'라고 한다. 스텝당 전환율이 높은 모델일수록 과적합 격차가 작기는 하다(모델 간 상관계수 -0.63). 하지만 이는 전환율이 높은 모델이 애초에 제출을 적게 하기 때문이다. 과적합 격차와 상관이 훨씬 강한 변수는 실행당 제출 횟수 중앙값이고(상관계수 0.84), 제출 횟수가 비슷한 모델끼리 비교하면 전환 비율은 과적합에 별다른 영향을 주지 못한다.

예를 들어 GPT-6 Astra는 제출 횟수가 GPT-5.6 Sol의 절반 수준인데, 이전 아이디어로 복귀하는 횟수는 두 배다. 그런데도 테스트 AUARC는 0.600으로 Sol의 0.513보다 높고, 과적합 격차는 1.7%로 Sol(6.9%)의 4분의 1이다.

![스텝당 전환율 및 실행당 제출 횟수 중앙값과 과적합 격차의 상관관계](https://img.seosoyoung.eiaserinnys.me/images/idea-basins-how-models-explore-ideas/05-overfitting-vs-volume.png)
*스텝당 전환율과 과적합 격차(위, ρ = -0.63) 및 실행당 제출 횟수 중앙값과 과적합 격차(아래, ρ = +0.84)의 관계. 과적합 격차는 검증 AUARC 대비 은닉 테스트 세트에서 손실된 점수의 비율이다. 출처: Bespoke Labs*

## 질문 3: 더 많이 탐색하면 실제로 점수가 높아지는가

아이디어 탐색과 실제 평가 점수 사이의 관계는 네 가지로 요약된다.

첫째, **전환의 빈도라기보다 '전환 중 새로운 분지를 시도하는 비율'이 성적을 결정한다.** 모델이 얼마나 자주 전환하는지(총 전환 횟수나 스텝당 전환율)는 최종 테스트 점수와 유의미한 상관관계가 없다. 반면 전체 전환 중 처음 시도하는 새 분지로 전환한 비중(신규 분지 전환 비중)이 높은 모델일수록 최종 테스트 AUARC도 높았다(모델 간 상관계수 0.70). 상위 4개 모델인 Opus 5.5, Claude Fable 5.1, GPT-6 Astra, Argon은 모두 이 비중이 70% 이상이었다.[^4] 특히 이 비중과 **초반 6시간 테스트 AUARC**의 상관계수는 0.84로, 이번 연구에서 측정한 모든 관계 중 가장 강했다.

![신규 분지 전환 비중과 초반 6시간 테스트 AUARC의 상관관계](https://img.seosoyoung.eiaserinnys.me/images/idea-basins-how-models-explore-ideas/06-new-share-vs-early-auarc.png)
*전체 전환 중 새로운 분지로 전환하는 비중과 초반 6시간 테스트 AUARC의 관계(ρ = +0.84). 전환 시 새로운 아이디어를 시도하는 모델일수록 초반에 훨씬 빠르게 높은 점수에 도달한다. 출처: Bespoke Labs*

둘째, **새로운 아이디어 분지로 전환하는 스텝 하나가 가져오는 기대 보상은 정제 스텝의 약 9배다.** 같은 분지를 유지하며 코드를 손보는 정제 스텝은 검증 점수가 평균 0.0082 오르는 데 그친다. 반면 새로운 분지로 전환하는 스텝은 평균 0.0708이 올라 정제 스텝의 8.6배, 즉 약 9배다. 이미 시도했던 분지로 복귀하는 스텝의 상승폭은 0.0133으로 정제 스텝과 큰 차이가 없다. 또한 현재 최고 점수의 90% 이상을 내는 정상 작동 제출물(working submission)에서 출발한 경우, 같은 분지를 유지한 스텝이 최고 점수를 경신한 비율은 30.2%다. 다른 분지로 전환한 스텝은 65.3%로 두 배 이상이다.[^5]

![스텝 유형별 검증 점수 변화량과 최고 점수 경신 확률 비교](https://img.seosoyoung.eiaserinnys.me/images/idea-basins-how-models-explore-ideas/07-payoff-of-switch.png)
*스텝 유형별 검증 점수 평균 변화량(위)과 정상 작동 제출물에서 출발해 최고 점수를 경신한 스텝의 비율(아래). 새로운 분지로 전환한 스텝(+0.071)은 같은 분지에서 정제한 스텝(+0.008)보다 점수 향상이 약 9배 크다. 출처: Bespoke Labs*

셋째, **아이디어 탐색과 그 보상은 초반 6시간에 집중된다.** 실행 시간대별 추이를 정리하면 아래 표와 같다.

| 실행 시간대 | 전체 스텝 중 전환 비율 (95% 신뢰구간) | 전환 스텝당 검증 점수 변화량 | 정제 스텝당 검증 점수 변화량 | 분석 대상 실행 수 |
| --- | --- | --- | --- | --- |
| 0시간부터 3시간 | 22.2% (17.1%–27.3%) | +0.104 (+0.063–+0.148) | +0.030 (+0.018–+0.042) | 269 |
| 3시간부터 6시간 | 10.5% (6.7%–14.8%) | +0.045 (+0.017–+0.088) | +0.012 (+0.005–+0.020) | 314 |
| 6시간부터 12시간 | 7.5% (4.9%–10.6%) | +0.005 (-0.007–+0.020) | +0.005 (+0.002–+0.009) | 324 |
| 12시간부터 24시간 | 5.7% (4.1%–7.6%) | +0.007 (-0.008–+0.018) | +0.002 (+0.0004–+0.005) | 324 |

전체 스텝 중 전환의 비중은 첫 3시간에 22.2%였다가 12시간 이후에는 5.7%로 급감한다. 점수 상승폭도 첫 6시간 동안은 전환 스텝이 정제 스텝의 약 3.5배였지만, 6시간이 지나면 두 스텝의 상승폭이 거의 같아진다.

![실행 시간대별 아이디어 전환 비중과 스텝당 검증 점수 변화량](https://img.seosoyoung.eiaserinnys.me/images/idea-basins-how-models-explore-ideas/08-timing-exploration.png)
*실행 시간대별 전체 스텝 중 전환 스텝의 비중(위)과 전환 대 정제 스텝의 평균 검증 점수 변화량(아래). 초반 6시간 이후에는 새로운 아이디어 탐색 빈도와 전환 시 기대 보상이 모두 급격히 감소한다. 출처: Bespoke Labs*

넷째, **후반부(12시간 이후)의 전환은 성적 향상으로 이어지지 않으며, 과반수의 실행이 최고 해법 분지를 끝내 찾지 못한다.** 12시간 이후에 분지를 전환한 실행은 55개였고, 이들의 후반부(12시간부터 24시간) 테스트 점수 상승폭은 평균 0.0084(중앙값 0.0021)였다. 기존 분지를 유지한 266개 실행은 평균 0.0140(중앙값 0.0026)이어서, 후반 전환이 더 높지는 않았다(상관계수 -0.04). 모델들이 초반에 탐색을 멈추고 일찍 정제만 하는 탓에, **전체 실행의 58%는 24시간 동안 한 번도 그 과제의 최고 해법이 속한 아이디어 분지를 시도하지 못했다.**

이 결과는 모델 학습과 에이전트 하네스 설계에서 어디를 개선해야 하는지 시사한다. 에이전트가 실행 초반에 새로운 아이디어를 더 적극적으로 탐색하도록 유도하고, 후반부에도 효과적인 탐색이 이어지도록 설계하면 장기 실행 과제의 성능 정체를 해소할 수 있다는 것이다.

## 가장 흥미로운 지점

내가 이번 분석에서 가장 눈여겨본 대목은 '제출 횟수'와 '아이디어 탐색'이 전혀 다른 변수로 작동한다는 점이다. 에이전트에게 24시간이라는 넉넉한 시간과 자율 실행 루프를 주면 모델이 스스로 여러 가설을 폭넓게 시험할 것 같다. 하지만 실제로는 제출을 3배 더 많이 하는 모델일수록 처음 고른 아이디어 하나를 수십 번 고쳐 쓰다가 검증 세트에 과적합된다. 반면 새 아이디어 분지로 전환하는 스텝은 정제 스텝보다 점수 상승폭이 평균 9배 가까이 크다. 그런데도 6시간이 지나면 새로운 시도가 급격히 줄고, 전체 실행의 58%는 최적의 해법 분지를 한 번도 시도하지 못한 채 끝난다.

장기 실행 에이전트의 성능이 왜 정체되는지도 이 데이터에서 읽을 수 있다. 모델의 코딩 능력이 부족해서라기보다, 컨텍스트에 누적된 이전 시도 기록이 다음 시도를 제약하기 때문이다. 하네스 수준의 개입이 왜 장기 연구 에이전트 설계의 핵심 과제인지, 이 연구는 명확한 숫자로 입증한다. 개입이란 *Fork and Flush*처럼 세션 컨텍스트를 주기적으로 비우고 분기시키거나, 후반부에도 새로운 아이디어 분지를 강제로 탐색하게 만드는 것이다.

[^1]: 자율 에이전트의 아이디어 고착(idea fixation)을 다룬 선행 연구인 *Fork and Flush*([arXiv:2610.07447](https://arxiv.org/abs/2610.07447))와 *Scaling Discovery Requires Forgetting*은 에이전트가 이전 시도에 고착되는 현상을 완화하기 위해 세션 컨텍스트를 주기적으로 삭제하고 분기시키는 기법을 제안했다.
[^2]: AutoResearchExam의 주 평가 지표인 AUARC는 24시간 실행 동안 모델이 제출한 해법들의 은닉 테스트 세트 점수 곡선 아래 면적을 평균한 값이다. 이번 분석에는 12개 프런티어 모델의 348회 실행(모델당 약 28회에서 29회, 각 24시간)에서 나온 채점 완료 제출물 12,656건을 썼다. 직전 제출물과 코드가 동일한 중복 제출을 뺀 유효 코드 변경 스텝은 9,179건이다. 전환율은 서로 다른 제출물이 3개 이상인 338회 실행으로 계산했다.
[^3]: 각 제출물은 최소 80개의 삼중항 질문에 포함되었으며, 순서 편향을 막기 위해 B와 C의 순서를 바꿔 두 번씩 질의했다. Nimble의 확신도가 낮은 응답을 제외하고 남은 569,271건의 삼중항 판정 중 90%로 과제별 2차원 t-STE 임베딩을 학습했다. 검증용으로 떼어 둔 10%에 대한 예측 정확도는 89%였으며, 각 제출물이 어느 실행에서 나왔는지만 아는 기준선(60%)을 크게 앞섰다. 어느 실행의 제출물인지만으로는 설명되지 않는 알고리즘 자체의 유사성까지 포착한다는 뜻이다. 과제별 분지 수는 실루엣 점수로 정했고, 3개에서 8개였다.
[^4]: 전체 전환을 단순 합산하면 절반가량이 이전 분지 복귀이지만, 복귀 스텝은 두 분지 사이를 여러 번 왕복하는 소수의 실행에 집중되어 있다. 따라서 실행별로 먼저 비율을 구한 뒤 평균을 낸 모델별 신규 분지 전환 비중은 12개 모델 모두 56.2%에서 85.0%로 50% 이상이다.
[^5]: 검증 점수 변화량은 가장 단순한 기준선(trivial baseline)을 0, 강력한 참조 해법(strong reference)을 약 0.5로 두고 정규화한 척도로 쟀다.
