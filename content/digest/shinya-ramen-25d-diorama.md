## 3줄 요약

1. Ashutosh Shrivastava가 2026년 11월 19일 웹 그래픽스 쇼케이스를 공개했다. 705KB짜리 정적 애니메이션 JPEG 일러스트(`1376×768`) 한 장만 입력으로 삼아, AI 영상 생성이나 외부 오디오 파일 없이 브라우저에서 60fps로 작동하는 2.5D 디오라마를 구축했다.
2. Apple Silicon에서 로컬로 구동한 `Depth-Anything-V2-Large`와 Python OpenCV(`GrabCut`, 가이드 필터, 영역 분리 인페인팅)로 원본 그림을 원근 배율을 맞춘 깊이 평면 5장과 시맨틱 RGB 마스크 7종으로 분해했다. 피사체에 가려진 벽면과 벽돌은 복원해 시차 이동 때 생기는 빈틈을 없앴다.
3. Three.js r187과 WebGL2 GLSL 셰이더 11개로 캐릭터의 호흡과 눈 깜빡임(`128×72` 정점), 물웅덩이 파동(`256×256` 천해 방정식, Shallow-Water PDE), 커서에 반응하는 노렌 커튼과 홍등 물리, Web Audio API 기반 공간 음향을 구현했다. 헤드리스 픽셀 검증에서는 실내 빗물 유입(빗줄기 픽셀 평균)이 `0.000`, 원본과의 RGB 상관계수 `rgbCorr`가 `0.9959`로 나왔다.

## 정적 일러스트 한 장에서 60fps 장면을 만드는 이유

평면 일러스트 한 장에 움직임을 불어넣을 때 흔히 쓰는 방식은 생성형 AI 비디오 모델에 이미지를 넣어 짧은 영상을 뽑아내는 것이다. 그러나 생성형 비디오는 시간이 흐를수록 인물의 이목구비가 일그러지고 선화가 흐릿해진다. 클라우드 비디오 API 호출 비용도 든다. 게다가 이미 렌더링된 MP4를 반복 재생할 뿐이라 사용자의 마우스나 터치 입력에는 실시간으로 반응하지 못한다.

Ashutosh Shrivastava는 Gemini 4 Neon 쇼케이스의 한 작품으로 「Shinya Ramen (深夜ラーメン)」을 공개했다. 이 작품은 비디오 생성 모델을 거치지 않고 컴퓨터 비전 전처리와 브라우저 셰이더를 결합해 이 문제를 풀었다.[^1] 입력은 비 내리는 밤거리의 라멘 가게를 그린 정적 JPEG 한 장(`1376×768`, 705KB)뿐이다. 3D 폴리곤 메시나 미리 녹음된 오디오 파일도 전혀 쓰지 않았다.

[^1]: 이 프로젝트는 저자가 Gemini 4 Neon 기수에서 제작한 WebGPU와 WebGL2 기반 인터랙티브 3D 월드 쇼케이스 17개 가운데 하나로 공개됐다.

![Apple Silicon에서 구동한 Depth-Anything-V2-Large와 OpenCV 가이드 필터로 추출한 단안 상대 깊이 맵](https://img.seosoyoung.eiaserinnys.me/images/shinya-ramen-25d-diorama/bts-02-depth.png)
*단일 JPEG에서 추정한 상대 깊이 맵. 따뜻한 색조는 가까운 전경(라멘 카운터와 인물)을, 차가운 푸른색은 먼 골목 배경을 나타낸다. 출처: [Ashutosh Shrivastava](https://ashutoshai.com/showcase/d/shinya-ramen)*

작업은 Apple Silicon GPU(MPS)에서 로컬로 `Depth-Anything-V2-Large`를 돌려 단안 상대 깊이를 추정하는 오프라인 비전 분해에서 출발한다. OpenCV 가이드 필터로 건물의 직선과 사물 윤곽선에 맞춰 깊이 경계를 날카롭게 정제한 뒤, Python 스크립트가 전경 인물과 소품을 투명 판으로 오려내고 가려진 뒷벽을 그려 넣는다. 브라우저에서는 Three.js r187과 WebGL2 커스텀 셰이더 11개가 60fps 고정 프레임으로 물리 효과를 계산하고, Web Audio API가 공간 음향을 합성한다.

## 깊이 평면 분리와 가려진 배경 복원

단일 이미지를 여러 장의 깊이 평면으로 분리해 카메라 시점을 흔들면, 앞쪽 피사체가 이동하면서 원래 피사체에 가려져 있던 뒤쪽 배경에 빈 구멍(disocclusion hole)이 드러난다. 시차(parallax)로 시점이 이동할 때 빈틈이 드러나지 않게 하려면 전경을 오려내는 작업과 가려진 배경을 메우는 작업을 한 묶음으로 설계해야 한다.

![전경 피사체를 지우고 주방 벽면과 목재 루버, 골목 벽돌을 복원한 배경 판](https://img.seosoyoung.eiaserinnys.me/images/shinya-ramen-25d-diorama/bts-03-inpainted.png)
*전경의 여성과 노렌 커튼, 홍등을 제거한 뒤 영역 분리 인페인팅으로 주방 벽면과 카운터 상판 테두리, 골목 벽돌을 채워 넣은 최후방 배경 판(`layer0`). 출처: [Ashutosh Shrivastava](https://ashutoshai.com/showcase/d/shinya-ramen)*

먼저 Python OpenCV의 `GrabCut` 알고리즘과 12픽셀 외곽선 확장(edge-bleed dilation)으로 전경 피사체 4종을 투명 PNG 판으로 분리했다. 이어 최후방 배경 판(`layer0`)에서 피사체를 덜어낸 영역은 구역별 샘플링 인페인팅(Zone-Split Inpainting)으로 채웠다. 실내 구역은 따뜻한 주방 벽면과 세로 목재 루버, 카운터 상판 테두리(counter lip)의 질감을 이어 붙여 복원하고, 실외 구역은 젖은 골목의 벽돌 패턴을 연장해 채웠다. 원본과 인페인팅된 배경 판 사이의 픽셀 평균 절대 차이는 `mean_abs_diff = 0.485`이다.

분리된 평면 5장은 Three.js의 `3.5833 × 2.000` 월드 프레임에 배치된다. 프레임 설정은 종횡비 `1.7917:1`, 카메라 거리 `d = 5.0`, 시차 오버스캔 `1.036`, 수평 이동 범위 `±0.26`, 수직 이동 범위 `±0.14`이다. 각 평면은 서로 다른 `z` 깊이에 놓이지만, 기본 정지 상태에서는 원본 일러스트와 픽셀 단위로 어긋남 없이 포개져야 한다. 이를 위해 각 평면의 크기에 원근 배율 공식 `(d - z) / d`를 곱해 정렬했다.

| 레이어 | Z 깊이 좌표와 원근 배율, 분리된 평면 구성 | 시차 보정과 렌더링 역할 |
|---|---|---|
| **layer0** | z = -0.36, 원근 배율 1.072, 최후방 네온 골목과 주방 배경 판 | 전경을 지우고 주방 뒷벽, 목재 루버, 골목 벽돌을 인페인팅 복원 |
| **layer1** | z = -0.05, 원근 배율 1.010, 처마 안쪽 고리의 후방 붉은 제등 판 | 처마 안쪽 고리를 축으로 바람과 커서 접촉에 흔들리는 후방 홍등 |
| **layer2** | z = +0.15, 원근 배율 0.970, 상단 봉에 매달린 6폭 노렌 커튼 판 | 상단 고리에 고정된 채 개별 폭 단위로 물결치며 커서에 휘어짐 |
| **layer3** | z = +0.20, 원근 배율 0.960, 처마 앞쪽 고리의 전방 붉은 제등 판 | 후방 홍등과 연성 진자 운동을 하며 따뜻한 발광 강도를 변조함 |
| **layer4** | z = +0.34, 원근 배율 0.932, 전경 여성과 라멘 카운터 전면부 판 | 턱을 괸 여성과 라멘 그릇, 스툴에 128×72 정점 리그 변형 적용 |

![투명 배경 위로 분리된 전경 인물과 라멘 카운터 컷아웃 판](https://img.seosoyoung.eiaserinnys.me/images/shinya-ramen-25d-diorama/bts-04-cutout.png)
*최전방(`z = +0.34`)에 배치되는 `layer4` 투명 컷아웃 판. 여성과 카운터, 라멘 그릇이 한 판으로 분리되어 `128×72` 정점 그리드로 변형된다. 출처: [Ashutosh Shrivastava](https://ashutoshai.com/showcase/d/shinya-ramen)*

가장 앞쪽의 `layer4` 판에는 Live2D 방식의 `128×72` 정점(vertex) 리그를 적용했다. 손바닥에 괸 턱을 고정 축(pivot)으로 삼아 고개가 미세하게 기울거나 끄덕인다. 어깨와 후드의 실루엣 전체는 호흡에 맞춰 오르내리고, 뒷머리와 앞머리는 바람에 흔들린다. 또한 눈동자는 마우스 커서 방향을 따라 조금씩 이동하고, 8배 슈퍼샘플링으로 제작한 눈꺼풀 패치가 3단계로 바뀌면서 눈이 자연스럽게 깜빡인다.

## 시맨틱 스텐실 7종과 WebGL2 셰이더 11개

2D 일러스트 위에 비, 물웅덩이, 발광(bloom) 셰이더를 장면 전체에 그대로 적용하면 포장마차 실내 카운터에 비가 내리거나 마른 나무 바닥에 물결이 이는 오류가 생긴다. 이를 막으려고 Python OpenCV와 NumPy(HSV 색공간 필터링, Canny 엣지, Black-Hat 변환, 형태학적 보호 마스크)로 시맨틱 RGB 스텐실 마스크 7종과 주요 소품의 정규화 픽셀 좌표를 추출했다. 마스크는 `1376×768` 해상도이고 `A=255`로 채널을 패킹했다.

![빗줄기, 물웅덩이, 네온 발광, 노렌 커튼, 인물 움직임 영역을 색상으로 구분한 시맨틱 스텐실 마스크](https://img.seosoyoung.eiaserinnys.me/images/shinya-ramen-25d-diorama/bts-05-stencils.png)
*색상별로 역할을 지정한 픽셀 스텐실. 파란색은 빗줄기가 허용되는 실외 골목, 청록색은 물웅덩이 파동이 일어나는 젖은 아스팔트, 분홍색은 네온 발광과 인물 호흡 및 머리카락 변형 구역, 초록색은 6폭 노렌 커튼을 가리킨다. 출처: [Ashutosh Shrivastava](https://ashutoshai.com/showcase/d/shinya-ramen)*

RGB 채널에 패킹된 이 마스크 7종은 비가 들이치지 않는 건조한 실내 포장마차와 비 내리는 골목, 깊은 안개, 젖은 아스팔트 노면을 픽셀 단위로 격리한다. 발광 간판과 제등 그룹 9개, 네온과 제등 반사광, 가스레인지 불꽃, 6폭 노렌 천, 전깃줄, 인물의 호흡 및 머리카락 구역, 실외기 그릴 창살 역시 채널별로 마스크를 따로 두어 다른 영역과 섞이지 않게 했다. 브라우저 렌더링은 `1/60`초 고정 시간 간격과 고정 난수 시드(`seed 19890417`)로 돌아가는 결정론적(deterministic) 시뮬레이션이다.

| 장면 구성 요소 | 파이프라인과 시뮬레이션 규격 | 작동 방식과 상호작용 |
|---|---|---|
| **젖은 아스팔트와 물웅덩이** | WebGL2 256×256 RGBA HalfFloat 핑퐁 PDE, 노이만 반사 연석과 벽면 경계 | 처마 낙수와 빗방울, 클릭과 드래그 물보라가 파동을 일으켜 도로 내부의 네온 반사광을 굴절시킨다. |
| **골목 빗줄기와 처마 낙수** | Three.js 인스턴스드 GLSL 셰이더, 7°\~15° 다중 깊이 결정론적 탄도 운동학 | 실내를 제외한 골목에만 빗줄기를 그리고, 양철 처마 골에서 떨어지는 물방울을 바닥 파동과 동기화한다. |
| **6폭 노렌 커튼과 쌍홍등** | 패널별 천 변형 GLSL과 커서 스프링, 처마 고리 축 기반의 연성 진자 운동학 | 노렌 6폭은 상단 고리에 고정된 채 바람과 커서에 휘어지고, 앞뒤 홍등 2개는 진자 운동으로 흔들린다. |
| **네온사인 깜빡임과 스파크** | 다중 마스크 발광 GLSL 셰이더, 배경 Z-릴리프 계수(-0.042) 연동 및 클릭 임펄스 | 간판 5종과 자판기가 깊이에 맞춰 확률적으로 깜빡이며, 클릭하면 전압 강하 암전과 함께 스파크가 튄다. |
| **김, 가스불, 안개, 환기팬** | 컬 노이즈 수증기 및 절차적 GLSL 셰이더, 실외기 그릴 마스크 기반 차폐 회전 | 라멘 그릇과 냄비의 김이 커서와 돌풍에 휘어지고, 가스불과 안개, 그릴 뒤의 환기팬 날개가 회전한다. |
| **골목 서사 이벤트와 후처리** | 결정론적 이벤트 운동학, 하늘 페더링 번개 GLSL, 풀스크린 열 아지랑이 후처리 | 주기적인 택시 전조등과 번개 암전 및 천둥을 연출하고, 버너 위 아지랑이 굴절과 원본 비교 커튼을 제공한다. |
| **절차적 공간 웹 오디오** | 외부 오디오 에셋 없는 100% Web Audio API 합성, 카메라 시차 연동 스테레오 패닝 | 빗소리와 처마 낙수, 육수 끓는 소리, 120Hz 네온 험 노이즈, 천둥, 열차음, 주방 로파이 라디오를 합성한다. |

사용자 인터페이스(Cinema Glass HUD)는 데스크톱과 모바일(`375×812` 바텀 시트)에 대응한다. 화면에서는 분위기 프리셋 4종(`Drizzle`, `Typhoon`, `3AM`, `Steam`)과 환경 슬라이더 5개(강우 강도, 바람, 네온 깜빡임, 수증기, 시차 깊이)를 조절할 수 있다. 레이어와 마스크 인스펙터도 함께 두어 6가지 뷰 모드(`Final`, `No-Post`, `Depth`, `Masks`, `Emissive`, `Original`)와 레이어별 개별 토글 7종을 실시간으로 켜고 끌 수 있게 했다.[^2]

[^2]: 캔버스를 직접 드래그해 시차를 조종하고, 마우스 휠이나 핀치로 줌을 `1.0`배에서 `1.18`배까지 조절할 수 있다. 키보드 단축키로는 원본 비교 커튼(`C`), 오디오 및 로파이 라디오(`M`), 일시정지(`Space`), HUD 숨김(`H`), 인스펙터(`D`)를 바로 전환할 수 있다.

## 색감 보존과 헤드리스 자동 검증

2D 일러스트를 3D 렌더러로 가져올 때 톤매핑이나 정점 변형 과정에서 원본의 색감과 펜선이 흐려지기 쉽다. 원본 팔레트를 그대로 유지하기 위해 렌더러에는 `SRGBColorSpace`와 `NoToneMapping` 조합을 지정했다. 정점 리그 때문에 픽셀이 이동한 캐릭터 영역에는 주변부 클램핑을 건 5탭 CAS(Contrast Adaptive Sharpening) 필터를 적용해 선화 선명도를 복원했다.

렌더링 품질과 마스크 경계 누출은 사람의 눈에만 맡기지 않고, Apple M5 Max(ANGLE Metal WebGL2) 환경의 헤드리스 자동 검증 스위트로 측정했다. 드로 콜은 19개, 삼각형은 57,792개였고 프레임은 60.0fps를 유지했다. 주요 검증 지표는 다음과 같다.

## 가장 흥미로운 지점

내가 눈여겨본 것은 시각 효과를 구현한 뒤 그 경계 조건을 테스트 코드로 검증한 방식이다. 2.5D 셰이더 작업에서는 빗줄기가 처마 안쪽 라멘 카운터에 겹쳐 보이거나 아스팔트 물웅덩이의 반사광이 옆 벽면으로 번지는 현상이 흔히 생긴다. 저자는 이를 막으려고 RGB 스텐실 마스크 7종을 설계하는 데 그치지 않고, 헤드리스 브라우저 검증 항목으로 `rain-leak-guard`와 `puddle-containment`를 따로 두었다. 그 결과 실내 빗물 유입과 도로 외부 파동 유출이 모두 `0.000`임을 수치로 확인했다. 여기에 더해 고장 주입 검증(Sabotage verification)도 거쳤다. 테스트가 아무것도 잡아내지 못한 채 통과하는 일이 없도록, 일부러 망가뜨린 픽스처 8종을 넣어 실패를 정확히 잡아내는지 확인했다.

생성형 비디오 모델에 이미지를 맡기면 그럴듯한 움직임을 쉽게 얻을 수 있지만, 선화의 선명도(`sharpRatio = 0.879`)나 색감 상관계수(`rgbCorr = 0.9959`)를 제어하거나 라멘 그릇의 김을 커서로 휘젓는 상호작용을 넣기는 어렵다. 오프라인 전처리 단계에서 깊이 맵을 뽑을 때만 AI 모델을 쓰고, 브라우저에서 돌아가는 시각 효과와 공간 음향은 결정론적 물리 방정식과 WebGL2 셰이더, Web Audio 합성으로 직접 짰다. 덕분에 정적 일러스트 한 장이 품고 있던 펜선과 색감이 60fps 상호작용 환경에서도 흐려지지 않고 살아난다.
