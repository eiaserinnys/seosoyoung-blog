## 3줄 요약

1. 사이오닉 AI(Sionic AI)는 30억 매개변수(3B) 소형 언어 모델 `Nanbeige4.2-3B`에 그룹 상대 정책 최적화(GRPO) 강화학습을 적용해 수학 추론 모델을 학습시켰다. 학습이 끝난 뒤 치러진 2027학년도 대학수학능력시험 수학 영역으로 성능을 검증했고, 학습된 체크포인트를 허깅페이스에 공개했다.
2. 학습 데이터는 2017\~2026학년도 기출 문항과, 독립 풀이에서 답이 일치해 검증된 합성 변형 문항이다. 이 중 당시 모델이 8회 풀었을 때 1\~7회만 맞히는 문항, 곧 정답과 오답이 함께 나오는 문항만 골라 2단계로 강화학습을 진행했다.
3. 문항마다 16회 샘플링해 평가한 결과, 1차 강화학습 체크포인트(40스텝)는 확률과 통계, 미적분, 기하 세 선택과목 모두 다수결 채점에서 100점을 받았다. 다수결을 쓰지 않고 풀이를 하나씩 채점했을 때 100점이 나온 횟수는 16회 중 확률과 통계 4회, 미적분 5회, 기하 2회였다.

## 연구 배경과 학습 데이터 선별: 현재 모델이 가끔 맞히는 문항만 고른다

30억 매개변수(3B) 안팎의 소형 모델은 휴대폰이나 엣지 디바이스에서 외부 서버 없이 실행할 수 있고 메모리도 적게 쓴다. 하지만 여러 단계의 논리 전개가 필요한 고난도 수학 추론에서는 대형 모델보다 불리하다고 여겨져 왔다. 사이오닉 AI 연구진은 같은 3B 모델이라도 사후학습(post-training)의 데이터 선별, 강화학습 설계, 추론 단계의 답안 집계 방식에 따라 고난도 수학 문제를 얼마나 풀 수 있는지 확인하기 위해 대학수학능력시험 수학 영역을 평가 과제로 골랐다.

수능 수학은 공통 22문항과 선택과목(확률과 통계, 미적분, 기하)별 8문항을 합쳐 과목당 30문항, 100점 만점으로 구성된다. 모든 문항이 5지선다 객관식이거나, 0 이상 999 이하의 정수를 답하는 단답형이다. 정답 일치 여부가 명확하므로 자동 채점으로 강화학습 보상을 만들기에 알맞다. 연구진은 `Nanbeige/Nanbeige4.2-3B`를 백본 모델로 삼아 2027학년도 수능 시행 전에 학습을 마쳤다. 시험에 미칠 사회적 영향을 고려해, 학습된 가중치와 실험 기록은 본시험이 끝난 뒤인 2026년 11월 20일에 공개했다[^1]. 도형이나 함수 그래프 같은 그림이 포함된 문항은 시각 조건을 텍스트 설명으로 변환해 입력했다.

[^1]: 공개된 저장소는 두 가지다. 하나는 2차 강화학습 중간 체크포인트(BF16 가중치 및 8비트 양자화 GGUF 포함)인 [`sionic-ai/sionic-K-SAT-MATH-3B`](https://huggingface.co/sionic-ai/sionic-K-SAT-MATH-3B)이고, 다른 하나는 2027학년도 수능에서 다수결 만점을 기록한 1차 강화학습 체크포인트를 8비트로 양자화한 [`sionic-ai/sionic-K-SAT-MATH-3B-v1-Q8_0-GGUF`](https://huggingface.co/sionic-ai/sionic-K-SAT-MATH-3B-v1-Q8_0-GGUF)다.

학습 데이터는 공식 기출 문항과 이를 바탕으로 생성한 합성 변형 문항 두 갈래로 준비했다. 기출 문항은 2017\~2026학년도 수능, 평가원 모의평가(6월과 9월), 교육청 학력평가(3월, 4월, 7월, 10월)의 수학 시험지 PDF에서 개별 문항을 추출했다. 추출한 문항은 이미지 전사(OCR)를 거친 뒤 PDF 텍스트 레이어의 한글과 숫자에 대조해 전사 오류를 바로잡았고, 정답은 공식 정답표의 값만 썼다. 합성 변형 문항은 기출의 난이도를 높인 고난도 변형과 풀이 단계를 쉽게 만든 디딤돌 문항, 수식과 기호의 표기 변형, 수학 용어 확인 문항으로 구성했다. 합성 문항은 문제를 만든 모델이 함께 내놓은 답을 그대로 믿지 않았다. 대신 모델에 정답을 알려 주지 않고 독립적으로 4회 풀게 해, 3회 이상 답이 일치한 문항만 학습 후보로 채택했다.

| 데이터 구분 | 세부 출처 및 검증 규칙 | 강화학습 투입 기준 |
| --- | --- | --- |
| 공식 기출 문항 | 2017\~2026학년도 수능, 6월과 9월 모의평가, 3월, 4월, 7월, 10월 학력평가 PDF 전사 및 텍스트 레이어 대조 교정, 공식 정답표 사용 | 당시 정책 모델로 8회 풀이 시 1\~7회 정답 문항만 선별 |
| 합성 변형 문항 | 기출 기반 고난도 변형, 디딤돌(쉬운 변형), 표기 변형, 수학 용어 문항. 4회 독립 풀이 중 3회 이상 답이 일치한 문항만 채택 | 당시 정책 모델로 8회 풀이 시 1\~7회 정답 문항만 선별 |
| 평가 및 검증 분리 | 2026학년도 수능(테스트), 2026학년도 9월 모의평가(검증) 및 두 시험에서 파생된 모든 변형 문항 | 전 학습 단계에서 영구 제외 (최종 평가는 학습 후 공개된 2027학년도 수능으로 수행) |

문항 정합성 검증 못지않게 중요한 단계는 당시 모델 수준에 맞는 난이도 선별이었다. 같은 문제를 여러 번 풀었을 때 매번 맞히는 문항은 추가 학습으로 얻을 개선 폭이 작고, 매번 틀리는 문항은 정답 풀이와 오답 풀이를 비교할 보상에 차이가 생기지 않는다. 연구진은 당시 정책 모델로 각 문항을 8회 풀어 1\~7회만 정답을 맞힌 문항, 곧 때로는 맞히지만 늘 맞히지는 못하는 문항만 추려 강화학습 세트를 꾸렸다.

## 2단계 GRPO 강화학습, 그리고 학습기와 생성 엔진의 가중치 동기화

강화학습 알고리즘으로는 그룹 상대 정책 최적화(GRPO, Group Relative Policy Optimization)를 사용했다. 지도학습은 풀이 문장마다 사람이 중간 과정 점수를 매기거나, 더 큰 교사 모델의 풀이 텍스트를 그대로 모방하게 한다. 반면 GRPO는 같은 문항에서 풀이(rollout)를 여러 개 샘플링해 각 풀이의 최종 답이 정답과 일치하는지만 채점하고, 그 결과를 집단 내 상대 보상으로 삼아 정책 가중치를 업데이트한다. 단답형은 0 이상 999 이하의 정수를, 객관식은 1\~5 중 하나의 선택지 번호를 `\boxed{}` 상자 표기 안에 넣도록 프롬프트를 통일해 최종 답안을 추출했다.

![같은 문항에서 여러 풀이를 생성하고 최종 답의 정답 여부 보상을 비교해 정책을 업데이트하는 GRPO 흐름](https://img.seosoyoung.eiaserinnys.me/images/sionic-ksat-math-rl-3b/02-grpo-desktop.png)
*그림 2: SGLang 엔진이 한 문항에 대해 여러 풀이를 생성하고, 최종 답이 맞았는지에 따라 보상(1 또는 0)을 매겨 비교한다. veRL 학습기가 이를 바탕으로 정책을 업데이트하면 새 가중치가 생성 엔진에 반영되는 순환 구조다. (출처: Sionic AI)*

GRPO가 유효한 기울기 신호를 얻으려면 한 문항에서 생성한 풀이 집단 내에 정답(보상 1)과 오답(보상 0)이 함께 존재해야 한다. 학습이 진행돼 모델의 수학 추론 능력이 올라가면, 처음에는 일부만 맞히던 문항도 8회 모두 맞히게 된다. 그러면 학습 신호가 사라진다. 연구진은 이 문제에 대응해 강화학습을 2단계로 설계했다. 먼저 1차 강화학습으로 40스텝(4 에폭)을 학습하고, 이어서 개선된 1차 모델(40스텝)로 전체 문항의 정답률을 다시 측정했다. 그 결과 여전히 일관되게 풀지 못하는 고난도 문항 위주로 2차 학습 세트를 재구성했다[^2].

[^2]: 난이도 사전 측정이 끝나지 않은 768문항은 기존 측정에서 학습 가치가 높게 나타난 고난도 번호대의 문항만 골라 2차 학습 후보에 포함했다. 이 가운데 모델이 전부 맞히거나 전부 틀리는 문항은 학습 중 DAPO 동적 샘플링이 자동으로 걸러낸다.

| 학습 단계 | 학습 문항 구성 | 주요 하이퍼파라미터 및 동적 샘플링 | 연산 규모 및 소요 시간 |
| --- | --- | --- | --- |
| 1차 RL (원본 → 40스텝) | 총 683문항: 2022\~2026 기출 181개 + 2017\~2021 4점 기출 146개 + 검증된 합성 변형 356개 | GRPO, 문항당 8 rollout, temperature 0.8, KL 페널티 없음, clip 0.2/0.28, token-mean loss, 학습률 $1\times 10^{-6}$ | 스텝당 64문항 $\times$ 8 rollout (업데이트 4회), 최대 응답 32,768토큰, 40스텝(8$\times$B300 GPU 약 8.7시간) |
| 2차 RL (1차 40스텝 → 10스텝) | 총 1,145행(중복 제외 1,078문항): 기출 317개, 고난도 합성 562개, 디딤돌 131개, 표기 변형 25개, 용어 43개, 첫 단계 힌트 제공 문항 4개 | 정답률 25% 이하 67문항은 2배 복제(에폭당 16 rollout), clip-high 0.28 → 0.20 하향, DAPO 동적 샘플링 적용 | 스텝당 64문항 $\times$ 8 rollout, 최대 응답 32,768토큰, 스텝당 약 36분(10스텝까지 약 6시간) |

2차 강화학습에서는 고난도 문항의 샘플링 비중과 클리핑 범위, 배치 구성 방식을 1차와 다르게 설정했다. 첫째, 1차 모델 기준 정답률이 25% 이하인 최상위 난이도 67문항은 데이터셋에 2배로 복제해 에폭당 16회 rollout이 돌아가도록 비중을 높였다. 둘째, 1차 학습 중 정책 엔트로피가 0.12에서 0.20으로 상승한 점을 감안해 상한 클리핑 계수(clip-high)를 0.28에서 0.20으로 낮췄다. 셋째, DAPO 동적 샘플링(dynamic sampling)을 도입했다. 학습 도중 생성된 8개 풀이가 전부 정답이거나 전부 오답인 문항 그룹은 즉시 제외하고, 유효한 문항으로 배치를 다시 채우는 방식이다.

학습 프레임워크로는 `veRL`을, 대규모 병렬 풀이 생성 엔진으로는 `SGLang`을 결합했다. 연구진은 백본인 `Nanbeige4.2-3B` 구조를 학습 환경에 맞게 이식하면서, `veRL` 학습기가 업데이트한 가중치가 매 스텝 `SGLang` 생성 엔진에 정확히 동기화되는지 별도로 검증했다. 학습기가 정상적으로 가중치를 업데이트하더라도 생성 엔진이 이전 스텝의 가중치로 풀이를 계속 생성하면 현재 정책을 평가하고 업데이트하는 온폴리시(on-policy) 가정이 깨지기 때문이다.

## 2027학년도 수능 수학 평가 결과: 세 선택과목 모두 다수결 100점

2026년 11월 19일에 2027학년도 수능 문제와 정답이 공개되자, 연구진은 공통 22문항에 선택과목 3종(확률과 통계, 미적분, 기하)의 8문항씩을 더해 중복을 제외한 46문항의 평가 세트를 만들었다. 평가는 서버의 BF16 정밀도 환경에서 진행했다. 대상은 원본 모델(`Nanbeige4.2-3B`), 1차 강화학습 체크포인트(40스텝), 2차 강화학습 중간 체크포인트(10스텝, `sionic-K-SAT-MATH-3B`) 세 가지다. 세 모델에 같은 생성 조건(temperature 0.6, top\_p 0.95, top\_k 20, 추론 모드 활성화, 최대 생성 길이 65,536토큰)을 적용해, 문항마다 풀이 16개를 독립적으로 생성했다. 각 선택과목 점수는 공통 22문항과 해당 선택과목 8문항을 합산한 30문항(100점 만점) 기준이다.

| 평가 대상 모델 | 확률과 통계 (16회 평균 / 다수결) | 미적분 (16회 평균 / 다수결) | 기하 (16회 평균 / 다수결) | 단일 회차 만점 횟수 및 특이사항 |
| --- | --- | --- | --- | --- |
| 원본 모델 (`Nanbeige4.2-3B`) | 94.0점 / 96점 | 93.5점 / 96점 | 92.6점 / 96점 | 공개 기록 없음 (다수결 96점) |
| 1차 RL 체크포인트 (40스텝) | 96.8점 / 100점 | 96.8점 / 100점 | 95.5점 / 100점 | 16회 중 확률과 통계 4회, 미적분 5회, 기하 2회 만점 |
| 2차 RL 중간 체크포인트 (10스텝) | 95.5점 / 96점 | 95.2점 / 96점 | 95.2점 / 96점 | 공통 21번(4점) 16회 모두 오답으로 다수결 96점 |

문항마다 16회 생성한 답안 중 가장 많이 나온 답을 골라 채점한 다수결(majority voting) 평가에서 1차 강화학습 체크포인트(40스텝)는 확률과 통계, 미적분, 기하 세 선택과목 모두 100점을 달성했다. 16회 실행의 단순 평균 점수도 원본 모델(92.6\~94.0점)보다 2.8\~3.3점 올라 95.5\~96.8점이었다. 다수결 없이 풀이를 하나씩 채점해도 16회 중 확률과 통계는 4회, 미적분은 5회, 기하는 2회 만점이 나왔다.

2차 강화학습 중간 체크포인트(10스텝)는 46문항 전체의 평균 정답률이 원본 모델의 93.8%에서 97.0%로 높아졌다. 선택과목별 16회 평균 점수도 95.2\~95.5점으로, 원본보다 1.5\~2.6점 올랐다. 그러나 공통 21번(4점 문항)을 16회 모두 틀린 탓에, 다수결 점수는 세 과목 모두 96점이었다[^3].

[^3]: 2차 강화학습 중간 체크포인트는 테스트 세트로 분리해 두었던 2026학년도 수능에서는 1차 체크포인트보다 평균 풀이 생성 길이가 줄었고 점수는 올랐다. 그러나 학습 후 새로 치러진 2027학년도 수능에서는 1차 체크포인트보다 점수가 낮았다. 연구진은 학습 효과를 정확히 해석하려면 풀이 길이와 정답률, 새 시험 문항에 대한 일반화 성능을 함께 확인해야 한다고 덧붙였다.

## 긴 풀이와 정답률의 관계, 그리고 실패한 대안 실험들

강화학습 초기 실험에서 연구진은 최대 응답 생성 길이를 48,000토큰으로 설정했다. 그러자 모델의 평균 풀이가 28,000토큰까지 길어져 1스텝 학습에 55분이 걸렸다. 생성 상한을 32,768토큰으로 낮춘 뒤, 상한에 걸려 중간에 잘린 풀이 700개를 전수 분석했다. 같은 문장을 무의미하게 되풀이하는 단순 반복 오류는 1.4%에 그쳤다. 나머지 98.6%는 여러 풀이 경로를 탐색하거나 복잡한 대수 계산을 계속 이어가다가 토큰 예산을 소진한 사례였다. 더구나 이렇게 잘린 풀이의 60%는 같은 문항을 다른 샘플링 회차에서 풀었을 때 정상적으로 정답에 도달한 경우였다.

| 실험한 학습 및 추론 접근법 | 설계 의도 | 3B 모델 검증 결과 및 원인 |
| --- | --- | --- |
| 생성 상한 축소(48,000 → 32,768) 및 미완성 풀이 0점 보상 | 비효율적으로 길어지는 탐색 경로 억제 | 채택: 단순 반복(1.4%)이 아닌 비효율적 우회 풀이(98.6%)에 페널티로 작동해 풀이 길이 단축 유도 |
| 1차 RL 모델의 정답 풀이 지도학습 (SFT) | 성공한 짧은 정답 궤적을 직접 학습시켜 효율화 | 기준 모델 대비 검증 성능 하락: 짧게 쓰는 표면 형식만 모방할 경우 추론 능력 유지 실패 |
| 대형 교사 모델의 추론 과정 증류 (Distillation) | 더 큰 모델의 정교한 풀이 과정을 3B 모델에 이식 | 기준 모델 대비 검증 성능 하락: 3B 백본의 표현 용량과 큰 모델의 문제 해결 방식 간 불일치 |
| 외부 Python 코드 실행 도구 연동 | 복잡한 수식과 수치 계산을 코드 실행으로 위임 | 기준 모델 대비 검증 성능 하락: 잘못된 Python 코드 작성과 도구 호출 실패가 추가 오류 유발 |

모델이 정답을 맞힐 역량이 있는 문항이라도 비효율적인 추론 경로를 고르면 토큰 예산만 다 쓰고 풀이 중간에 멈춘다. 연구진은 최대 길이를 32,768토큰으로 제한하고, 상한에 걸려 답을 내지 못한 풀이에는 0점 보상을 주었다. 길게 늘어지는 풀이가 보상을 받지 못하게 되자 모델은 더 짧은 풀이 경로를 선택하기 시작했고, 평가 단계의 평균 생성 길이도 함께 줄어들었다.

반면 추론 길이나 풀이 방식을 인위적으로 교정하려 한 다른 대안 실험들은 위 비교표처럼 3B 규모에서 오히려 성능을 떨어뜨렸다. 1차 모델이 맞힌 정답 풀이만 모아 지도학습(SFT)을 한 실험, 더 큰 모델의 추론 과정을 증류(distillation)한 실험, Python 인터프리터 도구를 붙인 실험은 모두 기준 모델보다 검증 성능이 낮았다. 3B 규모에서는 외부 도구나 대형 모델의 풀이 데이터를 그대로 가져와도 성능이 오르지 않았고, 백본 모델이 스스로 생성할 수 있는 풀이 분포에 맞춰 보상만 부여할 때만 정답률이 개선됐다.

한편 연구진은 3B 모델이 온디바이스에서 돌아가는지 확인하려고, 삼성 갤럭시 Z 폴드7(Galaxy Z Fold7)에서 `llama.cpp`로 원본 모델의 4비트 양자화 파일(용량 2.54GB)을 실행했다. 이때 외부 서버 연결은 쓰지 않았다. 또한 1차와 2차 강화학습 체크포인트의 8비트 양자화 파일(`Q8_0`, 용량 약 4.13GiB)도 함께 배포했다. 이 8비트 모델은 F16 원본과의 쿨백-라이블러 발산(KL divergence)이 0.0010에 불과해, 양자화로 인한 정확도 손실이 거의 없다[^4]. 연구진은 모바일 기기의 NPU와 GPU 가속을 함께 쓰면 8비트 양자화 모델로도 정확도 손실 없이 실시간 풀이가 가능한 속도에 이를 것이라고 전망했다. 이를 확인할 후속 기기 실측 결과도 예고했다[^5].

[^4]: 허깅페이스 모델 카드의 기술 노트에 따르면, 퀄컴 GenieX 내장 버전을 포함한 `llama.cpp`에는 SentencePiece 토크나이저 버그가 있다. 특수 토큰 뒤에 공백 기호(`▁`)를 임의로 붙여서, 학습 때와 입력 토큰열이 달라진다. 온디바이스나 로컬 `llama.cpp`에서 재현하려면 저장소에 동봉된 패치(`mobile/patches/llama-vocab-spm-prepend-first.patch`)를 적용하고, 컨텍스트 길이는 32,768, KV 캐시는 `q8_0`으로 설정해야 한다.

| 실행 환경 및 양자화 형식 | 파일 크기 및 정밀도 특성 | 구동 조건 및 비고 |
| --- | --- | --- |
| 스마트폰 온디바이스 4비트 양자화 (Galaxy Z Fold7) | 2.54GB (원본 3B 모델 4비트 GGUF) | `llama.cpp` 기반 구동, 외부 서버 연결 없이 기기 단독 추론 확인 |
| 로컬 및 모바일 가속용 8비트 양자화 (`Q8_0` GGUF) | 4.13GiB (F16과의 KL 발산 0.0010으로 손실이 거의 없음) | 컨텍스트 길이 32,768 및 `q8_0` KV 캐시 권장, `llama.cpp` 토크나이저 공백 패치 필수 |
| 평가 서버 환경 (`BF16`) | 16비트 부동소수점 원본 정밀도 | `SGLang` 기반, 최대 생성 65,536토큰 및 문항당 16회 샘플링 다수결 평가에 사용 |

[^5]: 연구진은 이번 100점 기록이 서버 BF16 환경에서 문항당 최대 65,536토큰으로 풀이를 16회 생성하고 다수결로 집계한, 추가 추론 연산의 결과라고 밝혔다. 따라서 시험 점수만으로 모바일 기기의 실시간 응답 속도와 단일 추론 정확도까지 확보했다고 단정해서는 안 된다고 덧붙였다.

## 가장 흥미로운 지점

이번 기술 보고서는 성공한 GRPO 설정뿐 아니라 추론 길이를 줄이려다 검증 점수가 떨어진 세 가지 실패 실험을 상세히 남겼다. 흔히 소형 모델의 수학 성능을 높이는 방법으로는 대형 교사 모델의 풀이 과정을 증류하는 것, 계산 실수를 줄이도록 Python 코드 실행 도구를 붙이는 것이 먼저 거론된다. 그러나 이번 3B 실험에서는 대형 모델 증류와 자기 정답 지도학습(SFT), Python 도구 연동 세 가지가 모두 기준 모델보다 검증 성능을 떨어뜨렸다. 3B 모델이 잘못된 코드를 짜거나 도구 호출에 실패해서 생긴 오류가, 암산 오류보다 더 큰 문제였다. 규모가 큰 모델의 풀이 방식을 억지로 따라 쓰게 하는 것도 소형 백본에는 맞지 않았다. 대신 연구진은 모델 스스로 생성한 풀이 집단에서 정답과 오답을 비교하는 GRPO를 그대로 유지했다. 여기에 32,768토큰 상한을 초과한 비효율적 우회 풀이에 0점을 주는 단순한 제약을 추가하자, 풀이 길이가 실제로 줄었다.

출발점인 원본 백본 `Nanbeige4.2-3B`부터 이미 2027학년도 수능 수학에서 16회 평균 92.6\~94.0점, 다수결 96점을 받았다. 4비트로 양자화하면 2.54GB 파일 하나로 스마트폰에서 실행되는 3B 모델이 강화학습 전부터 30문항 중 29문항을 맞힌 셈이다. 연구진이 강화학습으로 해결해야 했던 과제는 처음부터 수학을 가르치는 일이 아닌, 마지막 남은 4점짜리 1\~2문항의 오답률을 낮추는 일이었다. 이를 위해 연구진은 모델이 8회 풀이 중 1\~7회만 맞히는 문항만 반복해서 추려내고, 매 스텝 `veRL` 학습기가 갱신한 가중치가 `SGLang` 생성 엔진에 지연 없이 반영되는지 검증하는 데 공을 들였다. 이미 전부 맞히거나 전부 틀리는 문항을 배치에서 계속 덜어내고 온폴리시 가중치 동기화를 유지한 작업이 96점과 100점의 차이를 만들었다.
