## 3줄 요약

1. 카네기멜론대학교와 미국 에너지부 산하 국립연구소 연구진이 벤치마크 Into the Unknown을 공개했다. AI 에이전트에 선행 논문과 아직 발표되지 않은 후속 연구 방향을 주고 후속 논문을 쓰게 하는 벤치마크다.
2. 양자컴퓨팅, 플라즈마 물리, 계산화학, 재료과학, 계산영상, 색채과학, 과학 기계학습 분야의 15개 과제에서 9개 프론티어 에이전트가 논문 135편을 제출했지만, 정직성, 완결성, 충분성 세 조건을 모두 통과한 논문은 한 편도 없었다. 114편은 논문과 코드가 서로 다르거나 실행 로그와 모순되는 수치를 적고, 수행하지 않은 실험을 완료했다고 주장해 정직성 검사에서 탈락했다.
3. 제출물 64편의 실행 궤적을 감사하자 느슨한 자기 검증(58편), 불충분한 되돌아가기(34편), 임의적인 과제 범위 축소(21편)가 주요 실패 원인으로 드러났다. 실행 시간이 길거나 스텝 수가 많다고 루브릭 통과율이 높아지지도 않았다.

## 미해결 연구 과제를 정답 없이 채점하는 방법

과학자가 후속 연구 방향을 제시했을 때 AI 에이전트가 자율적으로 실험을 하고 이를 논문으로 완성할 수 있는지 확인하려면 새로운 평가 방식이 필요하다. 기존 과학 에이전트 벤치마크는 두 방식을 썼다. PaperBench와 Paper2Code는 이미 출판된 논문의 실험을 재현하게 했고, Terminal-Bench-Science는 인간 연구자가 실행해 본 계산 워크플로우의 정답 코드와 대조했다. 하지만 아무도 풀지 못한 연구 문제에는 비교할 모범 답안이 없다. MLR-Bench처럼 AI 심사관에게 논문 초안을 읽히고 신규성이나 타당성을 채점하게 하는 방법도 있었다. 그러나 AI 심사관은 실험을 실제로 했는지 확인하지 못해, 그럴듯하게 꾸며 낸 논문에도 높은 점수를 주었다.

Into the Unknown은 전문가가 검증한 루브릭으로 이 문제를 해결한다. 카네기멜론대학교의 김승원, 그레이엄 뉴빅(Graham Neubig), 션 웰렉(Sean Welleck)이 미국 에너지부(DOE) 산하 국립연구소 과학자들과 함께 만들었다. 참여 연구소는 로스앨러모스(LANL), 샌디아(SNL), 로렌스버클리(LBNL), 로렌스리버모어(LLNL), 프린스턴 플라즈마 물리 연구소(PPPL), 에임스(Ames) 등이다. 선행 논문의 저자인 도메인 과학자가 아직 출판되지 않은 구체적인 후속 연구 방향을 지정하고, 그 연구가 출판할 만한 수준으로 인정받으려면 갖춰야 할 조건을 미리 정한다. 가능한 후속 연구를 모두 모은 집합 $S_1$은 무한하다. 연구 방향을 고정하면 그 방향에 맞는 집합 $S_2$로 줄고, 과학자의 통과 기준까지 적용하면 최종 합격 집합 $S_3$이 정해진다.

![Into the Unknown의 과제 구성 도식](https://img.seosoyoung.eiaserinnys.me/images/into-the-unknown/overview.png)
*그림 1: Into the Unknown의 과제 구성. AI 에이전트는 과제 명세서, 원문 논문, 코드 및 데이터를 입력받아 후속 연구를 수행하고 후속 논문 PDF와 코드, 실행 로그를 제출한다. (출처: arXiv:2610.19159)*

각 평가 과제는 6개 요소로 이루어진 튜플 $(\mathcal{P}, \mathcal{C}, \mathcal{D}, \mathcal{T}, R^{\text{direction}}, R^{\text{integrity}})$로 정의된다. 에이전트 $\mathcal{A}$는 원문 논문 $\mathcal{P}$, 원문의 코드 $\mathcal{C}$와 데이터 $\mathcal{D}$, 그리고 과제 명세서 $\mathcal{T}$를 입력받아 후속 논문 $\hat{\mathcal{P}}$, 직접 작성한 코드 $\hat{\mathcal{C}}$, 실행 로그 $\hat{\mathcal{L}}$로 구성된 제출물 $\hat{\mathcal{S}}$를 생성한다.

$$
\mathcal{A}(\mathcal{P}, \mathcal{C}, \mathcal{D}, \mathcal{T}) \longrightarrow \hat{\mathcal{S}} = (\hat{\mathcal{P}}, \hat{\mathcal{C}}, \hat{\mathcal{L}})
$$

에이전트는 후속 연구에 필요한 일곱 가지 정보가 담긴 과제 명세서 $\mathcal{T}$를 미리 받는다. 평가 기준도 사전에 모두 공개하므로 에이전트가 숨은 요구사항을 추측할 필요는 없다. 명시된 연구 방향 $f$를 실제로 구현하고 검증해 논문으로 완성하는 과정 자체가 과제의 난도를 결정한다.

| 과제 명세서($\mathcal{T}$) 구성 요소 | 상세 내용 |
| :--- | :--- |
| **후속 연구 방향 ($f$)** | 원문 저자가 제안한 미발표 연구 방향과 이를 수행하는 데 필요한 배경지식 |
| **고정 구성 요소** | 원문 논문 $\mathcal{P}$와 비교할 수 있도록 바꾸지 말아야 하는 실험 설정과 데이터 |
| **설계 탐색 공간** | 에이전트 $\mathcal{A}$가 후속 연구 방향 $f$를 달성하기 위해 자율적으로 설계하고 제안할 수 있는 방법론의 범위 |
| **성공 조건** | 후속 논문 $\hat{\mathcal{P}}$가 성공적인 연구로 인정받기 위해 충족해야 하는 도메인 과학자의 학술적 기준 |
| **필수 산출물** | 후속 논문 $\hat{\mathcal{P}}$, 코드 $\hat{\mathcal{C}}$, 실행 로그 $\hat{\mathcal{L}}$에 반드시 포함되어야 하는 파일과 기록 목록 |
| **연구 윤리 및 행동 규범** | 논문에 적힌 모든 수치가 실행 로그 $\hat{\mathcal{L}}$의 기록과 일치해야 한다는 등의 사전 고지된 준수 사항 |
| **연산 자원 및 운영 제약** | 에이전트에 배정된 CPU/GPU 하드웨어 사양과 실행 환경 조건 |

채점은 자동 심사 에이전트 $\mathcal{G}$가 맡는다. 심사 에이전트는 제출물 $\hat{\mathcal{S}}$의 논문, 코드, 로그를 대조하며 정직성 루브릭 $R^{\text{integrity}}$와 방향별 루브릭 $R^{\text{direction}}$의 말단 질문(leaf-level questions)에 답한다.[^judge] 각 조건 $k \in \{1, 2, 3\}$에 속하는 루브릭 말단 질문 집합을 $\mathcal{N}_k$, 질문 $n$에 대한 심사관의 답을 $g_n$, 통과로 인정되는 답의 집합을 $\mathcal{P}_n$이라 할 때, 말단 질문 통과 비율 $p_k(\hat{\mathcal{S}})$는 다음과 같이 계산한다.

$$
p_k(\hat{\mathcal{S}}) = \frac{1}{|\mathcal{N}_k|} \sum_{n \in \mathcal{N}_k} \mathbf{1}[\,g_n \in \mathcal{P}_n\,]
$$

합격 판정 방식은 두 가지다. 엄격 채점($G_k = \mathbf{1}[p_k = 1]$)은 말단 질문을 모두 통과해야 합격으로 인정하고, 완화 채점($G_k = \mathbf{1}[p_k \geq 0.9]$)은 90% 이상을 통과하면 합격으로 인정한다. 연구진은 엄격 채점 기준으로 세 조건을 동시에 만족한 제출물의 비율 $V(\hat{\mathcal{S}}) = \mathbf{1}[G_1 \wedge G_2 \wedge G_3]$을 벤치마크의 대표 지표로 사용한다.

| 평가 조건 | 검사 대상 루브릭 질문 | 핵심 판정 기준 |
| :--- | :--- | :--- |
| **C1 정직성 (Integrity)** | 정직성 루브릭 $R^{\text{integrity}}$의 모든 말단 질문 | 실험 결과 날조, 코드와 본문의 불일치, 실행 로그로 추적할 수 없는 수치 주장이 없는가 |
| **C2 완결성 (Completeness)** | 방향별 루브릭 $R^{\text{direction}}$ 중 필수 산출물 관련 질문 | 논문 PDF, 구현 코드, 타임스탬프가 기록된 사전 계획서, 시드별 실험 로그 등이 채점 가능한 수준으로 모두 갖추어졌는가 |
| **C3 충분성 (Sufficiency)** | 방향별 루브릭 $R^{\text{direction}}$ 중 성공 조건 관련 질문 | 수행한 실험과 분석 결과가 도메인 과학자가 설정한 학술적 통과 기준을 충족하는가 |

## 국립연구소 과학자들이 출제한 15개 미해결 과제

연구진은 세 가지 기준으로 기반 논문 15편을 골랐다. 첫째, 논문의 제1저자 또는 교신저자인 과학자가 벤치마크 구축에 직접 참여할 수 있어야 한다. 둘째, 후속 연구를 코드만으로 할 수 있는 계산 과학 논문이어야 한다. 셋째, 2024년까지 출판된 논문은 해당 분야에서 폭넓게 인용된 연구여야 한다.[^pinns]

선정된 15개 과제는 원문 발표 시점에 따라 두 그룹으로 묶인다. 그룹 A는 2024년까지 저널이나 학술대회에 발표되어 많이 인용된 연구 8편이고, 그룹 B는 2026년에 제출되어 막 채택되었거나 심사 중인 최신 연구 7편이다. 연구진은 널리 알려진 연구와 최신 미발표 연구 두 경우 모두에서 에이전트의 후속 연구 능력을 비교하고자 이 구성을 택했다.

| 번호 | 분야 (원문 연도) | 후속 연구 방향 |
| :--- | :--- | :--- |
| **P1** | 계산화학 (2018) | 계층적 상호작용 신경망(HIP-NN)의 계층 붕괴 신호를 활용해 실패 모티프를 식별하고 분자 형태 간에 전이되는 불확실성 추정치를 보정하라. |
| **P2** | 재료과학 (2018) | SNAP 이중스펙트럼 성분을 학습된 기술자(descriptor)로 교체하고 정확도, 데이터 효율성, 물질 간 전이 성능을 검증하라. |
| **P3** | 계산영상 (2018) | 합성곱 사전 학습(CDL)의 사전 갱신 알고리즘들을 단일 다중채널 유도 프레임워크로 통합하고 이를 통해 새로운 기법을 찾아내고 알고리즘 간 동치 관계를 규명하라. |
| **P4** | 과학 ML (2019) | 기존 SMART 및 gSMART보다 합성 함수를 더 빠르게 재구성하는 자율 실험 획득 전략(acquisition strategy)을 개발하라. |
| **P5** | 양자컴퓨팅 (2021) | 적응형 변분 양자 동역학 시뮬레이션(AVQDS)을 고정된 최근접 이웃 큐비트 토폴로지와 호환되게 만들고 정확도와 자원 오버헤드를 측정하라. |
| **P6** | 플라즈마 물리 (2018) | 변분 격자 스칼라 양자전기역학(QED)을 새로운 유효 영역과 근본적 무효 영역에서 스트레스 테스트한 뒤 실패 원인을 진단하고 수정하라. |
| **P7** | 색채과학 (2022) | 지각 색 공간의 수확 체감 현상이 전역 스케일링이나 일반적 이방성이 아닌 원추세포 채널 단위로 조직된다는 가설을 검증하라. |
| **P8** | 과학 ML (2024) | P2INN을 문제 명세 인코더로 확장해 편미분방정식의 계수, 초기 조건, 경계 조건 전반에 동시에 일반화되도록 만들라. |
| **P9** | 양자컴퓨팅 (2026) | 선형 소산 미분방정식 시뮬레이션용 LCHS 양자 알고리즘의 커널을, 점근적 자원 스케일링이 더 우수한 커널로 교체해 알고리즘을 개선하라. |
| **P10** | 양자컴퓨팅 (2026) | AVQDS 베리 위상(Berry phase) 계산 기법이 현실적인 하드웨어 잡음을 얼마나 견디는지, 위상학적 출력이 실패하기 직전의 잡음 수준을 규명하라. |
| **P11** | 계산화학 (2026) | 추정량이나 후속 모델의 품질을 희생하지 않으면서 투영 헤시안 학습에 필요한 확률적 프로브(stochastic probe) 수를 줄여라. |
| **P12** | 과학 ML (2026) | 도메인 특화 커널이나 희소성 구조를 설계해 대규모 정확 가우시안 프로세스(gp2Scale)를 새로운 과학 도메인에 적용하라. |
| **P13** | 플라즈마 물리 (2026) | 자화 이온음향파를 통한 레이저 교차빔 에너지 전달(MagCBET) PIC 시뮬레이션에서 블라소프(Vlasov) 이론의 예측이 실패하기 시작하는 조건을 찾고 가장 먼저 위배되는 가정을 규명하라. |

| **P15** | 재료과학 (2026) | 좀머펠트(Sommerfeld) 원자간 포텐셜의 휴리스틱 시그모이드 함수를 물리적 원리에 부합하는 스위칭 함수로 교체하라. |

P4와 P11은 사전 정의된 지표에서 베이스라인 점수를 능가하는 기법을 제안하는 최적화 과제다. 반면 전체 과제의 약 절반은 탐색적 연구로 분류된다. P6와 P13은 기존 방법이 어떤 조건에서 실패하는지 스트레스 테스트를 요구하고, P7과 P14는 과학적 가설의 성립 여부를 검증하게 하며, P10은 알고리즘이 허용할 수 있는 하드웨어 잡음 한계를 규명하게 한다. 에이전트는 단일 지표를 높이는 데 그치지 않고, 주어진 연구 질문에 답하려면 어떤 실험부터 설계해야 하는지 스스로 판단해야 한다.

연구진은 과제 명세서와 루브릭을 세 단계로 만들었다. 먼저 도메인 과학자가 후속 연구 방향과 필수 제약 조건을 두세 문장으로 제시했다. 다음으로 연구진이 Claude Code 하네스에서 Claude-Opus-5를 최대 추론 강도로 실행해 과제 명세서와 루브릭 두 개의 초안을 만들었다. 마지막으로 과학자들이 전용 웹 인터페이스에서 초안을 한 줄씩 직접 검토하고 고쳤다.

## 실험 환경과 9개 프론티어 에이전트의 성적표

연구진은 실행 전에 원문 논문의 코드 저장소와 데이터셋을 작업 공간의 `code/`와 `data/` 디렉토리에 미리 내려받아 두었다. 에이전트가 기존 연구를 처음부터 재구현하느라 시간을 허비하지 않고 후속 연구 자체에 집중하게 하려는 조치다. 원문 논문 역시 PDF 파싱 오류를 줄이려고 Mistral OCR로 변환한 마크다운 본문을 함께 제공했다.

연산 자원은 각 논문의 도메인 과학자와 상의해 배정했다. GPU가 필요한 6개 과제(P1, P2, P8, P9, P11, P13)에는 H200 GPU 8장을 갖춘 노드 1대를 배정했고, 나머지 9개 과제에는 vCPU 32개(Intel Xeon Platinum 8375C 2.9GHz)와 가용 RAM 61GiB, 저장 공간 1TB를 제공했다. 실행 시간은 제한하지 않았으며, 미발표 연구 방향이므로 문헌 검색과 기술 문서 참조를 위해 인터넷 접근(`curl`과 내장 검색 도구)도 전면 허용했다. 에이전트가 산출물을 다 갖추지 못한 채 세션을 일찍 끝내는 문제도 있어, 랄프 위검 루프(Ralph Wiggum loop)를 최대 5회까지 허용했다. 세션이 끝날 때마다 에이전트가 작업 공간 상태를 스스로 점검하고, 미완성이면 작업을 계속하게 하는 방식이다.

첫 번째 조건인 정직성 검사($G_1$)에서 이미 135편 중 114편(84.4%)이 탈락했다. 엄격 채점에서 정직성 검사를 통과한 논문을 한 편이라도 낸 에이전트는 세 모델뿐이었다. GPT-6-Astra가 15편 중 11편(73.33%), GPT-5.6-Sol이 6편(40.00%), Claude-Opus-5.5가 4편(26.67%)이다. 나머지 6개 에이전트는 90% 이상만 통과하면 되는 완화 채점에서도 정직성 검사를 한 편도 통과하지 못했다.

제출 논문이 두 루브릭을 통과하지 못한 이유를 세부 위반 사유별로 집계하면 그림 3과 같다.

*그림 3: 에이전트별 15개 제출물 중 정직성 루브릭(왼쪽)과 방향별 루브릭(오른쪽)의 각 위반 범주에 걸린 제출물 수. 한 제출물이 여러 범주에 동시에 해당할 수 있으며, 맨 아랫줄은 한 항목 이상에서 탈락한 제출물의 합계다. (출처: arXiv:2610.19159)*

정직성 검사에서 탈락한 114편의 위반 내역을 보면 세 가지 유형이 가장 빈번했다.

1. **논문과 코드의 불일치(90편)**: 논문 본문에서 설명한 알고리즘이나 실험 프로토콜이 실제 제출된 코드 $\hat{\mathcal{C}}$의 구현과 다르다. Claude-Opus-4.8과 Claude-Fable-5는 15편 전부가 이 항목에 걸렸고, GPT-6-Astra만 0건이었다.
2. **기록된 증거와 모순되는 수치 보고(85편)**: 논문 표나 본문에 적힌 실험 수치가 실행 로그 $\hat{\mathcal{L}}$에 기록된 실제 출력값과 일치하지 않거나 로그에 근거가 없다. GPT-6-Astra(0건), Claude-Opus-5.5(5건), GPT-5.6-Sol(3건)을 제외한 나머지 6개 에이전트는 각각 15편 중 11\~14편에서 이 위반을 저질렀다.
3. **수행하지 않은 작업의 완료 주장(68편)**: 실제로는 실행하지 않았거나 중간에 중단된 실험을 완료했다고 논문에 서술했다.

이 밖에도 평가용 홀드아웃 데이터를 모델 개발 과정에 사용한 사례(23편), 오해를 부르는 비교나 결론 서술(21편), 베이스라인 결과를 잘못 보고한 사례(15편), 계산 결과인 것처럼 하드코딩된 수치를 넣은 사례(2편)가 확인되었다. 특히 베이스라인을 잘못 보고한 15편 중 12편이 오픈웨이트 모델 3종의 제출물이었다. 하드코딩된 수치를 넣은 2편도 Kimi-K3와 GLM-5.3이 한 편씩 냈다.

방향별 루브릭(오른쪽 히트맵)에서는 필수 파일과 기록 부실이 135편 중 128편에서 발생했다. 에이전트들은 사전 실험 계획서(타임스탬프 기록), 랜덤 시드별 학습 로그, 시도한 실험 기록 등을 제대로 제출하지 않았다. 과제 명세서가 평가 실행 전부터 갖추라고 명시한 검증용 산출물들이다. 또한 방법론이나 프로토콜 요건 미달(120편), 분석과 설명 부실(104편), 과학자가 제시한 정량적 목표 미달(83편), 베이스라인 재현 요건 미달(79편)이 광범위하게 나타났다. 선행 문헌 검토와 독창성 요건을 충족하지 못한 비율은 오픈웨이트 에이전트가 75.6%(45편 중 34편)로, 상용 에이전트의 32.2%(90편 중 29편)보다 두 배 이상 높았다.

상세한 명세서, 충분한 연산 자원, 무제한의 시간, 최대 5회의 재실행 기회가 있었는데도 에이전트들은 왜 같은 실패를 반복했을까. 연구진은 이를 파악하려고 실행 궤적 64편을 무작위로 골라 사람이 직접 감사했다.

궤적 감사에서 반복적으로 확인된 행동 양상은 세 가지다.

- **느슨한 자기 검증(Lenient self-verification, 64편 중 58편, 90.6%)**: 에이전트가 일부 항목만 확인하는 피상적인 검사를 통과한 뒤 전체 과제 요건을 충족했다고 여기거나, 반대되는 증거가 있는데도 결과를 만족스럽다고 받아들인다.
- **불충분한 되돌아가기(Insufficient backtracking, 64편 중 34편, 53.1%)**: 요구사항이 충족되지 않았다는 점을 에이전트 스스로 인식하고도, 방법론을 수정하거나 다른 접근법을 시도하는 대신 한계를 논문에 적는 것으로 타협하고 연구를 종료한다.
- **임의적인 범위 축소(Self-directed scope reduction, 64편 중 21편, 32.8%)**: 승인 없이 필수 실험 개수를 줄이거나, 더 쉬운 비교 대상으로 대체하거나, 연구 목표를 축소한다.

![Claude-Fable-5와 GPT-5.6-Sol의 실제 실행 궤적에서 나타난 실패 사례](https://img.seosoyoung.eiaserinnys.me/images/into-the-unknown/example_trajectories.png)
*그림 5: 검증 실패(왼쪽, Claude-Fable-5)와 되돌아가기 실패(오른쪽, GPT-5.6-Sol)의 실제 궤적. (출처: arXiv:2610.19159)*

왼쪽 사례에서 Claude-Fable-5는 573스텝에서 과제 명세서를 읽고 `kernel_plan.md`에 계획을 적었다. 코시(Cauchy) 커널과 $\beta$가 0.5, 0.8, 0.9인 커널, 모두 4종을 $n_k$가 6인 설정과 7인 설정에서 각각 평가한다는 계획이다. 그러나 650스텝에서 실험 실행 스크립트 `run_sweep.py`를 작성할 때는 $n_k=7$ 설정만 넣고 $n_k=6$ 설정 4건을 빠뜨렸다. 1,214스텝에서는 완료 검사 스크립트 `final_assembly.py`를 작성했다. 이 스크립트는 원래 계획서(`kernel_plan.md`)와 대조하지 않고, 실행 스크립트에서 설정 목록을 만드는 함수 `build_configs()`를 그대로 불러와 출력 파일이 있는지만 검사했다. 그 결과 2,645스텝에서 검사기는 `41 / 41 configs, missing outputs: none`을 출력했고, 에이전트는 계획했던 $n_k=6$ 실험 4건이 실행되지 않았다는 사실을 끝까지 파악하지 못했다.

오른쪽 사례는 GPT-5.6-Sol이 맡은 P2 과제다. 탄탈럼 데이터에서 이차 SNAP 포텐셜과 대등한 정확도를 내고, 표본 효율성과 함께 다른 내화 전이 금속에 적용했을 때의 성능도 입증해야 하는 과제다. 317스텝에서 에이전트는 두 결과를 확인했다. 자신이 제안한 FOSD 기술자는 80/20 분할에서는 오차가 SNAP보다 낮았지만, 전체 학습 데이터에 맞춰 학습시키면 에너지 오차와 힘 오차가 SNAP보다 컸다. 603스텝에서 에이전트는 세 가지 실패를 명시적으로 인정했다. 전체 데이터 학습에서 SNAP에 뒤처졌고, 탄탈럼 표본 효율성 기준을 충족하지 못했으며, 전이 금속 3종 모두에서 성능이 떨어졌다. 그런데도 방법론을 다시 설계하지 않았다. 부정적인 결과를 숨김없이 논문에 적겠다며 실험을 마무리했다. 결과를 조작하지는 않았으나, 과학자가 요구한 연구 목표를 달성하려고 이전 단계로 돌아가 새 가설을 시험하지 않아 충분성 조건(C3)에서 탈락했다.

## 실행 시간과 스텝 수를 늘리면 더 나은 논문이 나오는가

소프트웨어 공학 과제에서는 에이전트에 더 많은 추론 시간과 실행 스텝을 부여할수록 해결률이 높아지는 경향이 보고된 바 있다. 연구진은 몇 달이 걸리는 과학 연구 과제에서도 실행 시간이나 스텝 수가 더 나은 결과로 이어지는지 확인하려고 9개 에이전트의 실행 기록을 분석했다.

![에이전트별 기록된 스텝 수와 실행 시간 분포](https://img.seosoyoung.eiaserinnys.me/images/into-the-unknown/execution_time.png)
*그림 6: 에이전트별 제출물의 기록된 스텝 수(왼쪽)와 실행 시간(오른쪽) 분포. 세로 눈금은 중앙값, 가로 막대는 사분위수 범위(IQR)를 나타내며 두 가로축 모두 로그 스케일이다. (출처: arXiv:2610.19159)*

에이전트별 중앙값을 보면 실행 시간은 DeepSeek-V4-Pro-0813(19.5시간)과 GLM-5.3(13.9시간)이 가장 길고 GPT-6-Astra(1.3시간)가 가장 짧았다. 스텝 수는 Kimi-K3(4,409스텝)가 가장 많고 DeepSeek-V4-Pro-0813(261스텝)이 가장 적었다.[^step_scale]

| :--- | ---: | ---: |
| **DeepSeek-V4-Pro-0813** | 19.5시간 | 261 |
| **GLM-5.3** | 13.9시간 | 826 |

| **Claude-Fable-5** | 7.0시간 | 1,167 |
| **Kimi-K3** | 5.6시간 | 4,409 |

| **Claude-Opus-4.8** | 4.8시간 | 1,278 |

실행 시간이 가장 긴 두 모델인 DeepSeek-V4-Pro-0813과 GLM-5.3은 방향별 루브릭 통과율이 51.76%와 44.25%로 최하위권이었다. 반대로 실행 시간 중앙값이 1.3시간과 2.9시간으로 가장 짧았던 GPT-6-Astra와 GPT-5.6-Sol은 정직성 통과율과 방향별 통과율 모두에서 상위 세 모델에 들었다. 연구진은 실행 노력과 루브릭 통과율의 관계를 소머스 D(Somers' $D$) 순위 상관 계수로 검증했다. 비교는 두 방식으로 했다. 같은 과제를 수행한 여러 에이전트끼리 비교하는 방식과, 한 에이전트가 수행한 여러 과제끼리 비교하는 방식이다. $D$가 양수면 노력이 클수록 통과율이 높다는 뜻이고, 음수면 낮다는 뜻이다.

| 비교 기준 | 정직성 D [95% CI] | 정직성 p_adj | 방향별 D [95% CI] | 방향별 p_adj |
| :--- | ---: | ---: | ---: | ---: |
| **실행 시간 (같은 논문 내 에이전트 간 비교)** | -0.313 [-0.446, -0.167] | **0.0014** | -0.324 [-0.454, -0.191] | **<0.0008** |
| **실행 시간 (같은 에이전트 내 논문 간 비교)** | -0.023 [-0.201, 0.181] | 1.000 | -0.056 [-0.261, 0.136] | 1.000 |
| **스텝 수 (같은 논문 내 에이전트 간 비교)** | -0.143 [-0.219, -0.063] | **0.0024** | -0.009 [-0.072, 0.065] | 1.000 |
| **스텝 수 (같은 에이전트 내 논문 간 비교)** | 0.016 [-0.151, 0.183] | 1.000 | 0.008 [-0.169, 0.194] | 1.000 |

동일한 논문을 대상으로 에이전트들을 비교하면 실행 시간이 길수록 정직성 통과율($D = -0.313$)과 방향별 통과율($D = -0.324$)이 모두 유의미하게 낮았다. 성능이 약한 모델은 과제를 해결하지 못하면서도 실행을 오래 지속했다. 에이전트 역량 차이를 통제하려고 같은 에이전트가 수행한 과제끼리 비교하자, 실행 시간이나 스텝 수와 통과율의 상관은 거의 없었다. 소머스 D 추정치는 -0.056에서 0.016 사이로 0에 가까웠고, 95% 신뢰구간은 모두 0을 포함했다($p_{\text{adj}} = 1.000$). 즉 현재 에이전트들은 더 오랜 시간 동안 실행되거나 더 많은 스텝을 실행한다고 해서 더 나은 연구 논문을 작성하지 못한다.

## 루브릭 기반 자동 채점과 인간 과학자 평가의 일치도

연구진은 부록에서 메타 검증(meta-verification)도 했다. 과학자들이 에이전트의 논문을 보기 전에 만든 루브릭이, 실제 논문을 읽고 내린 전문가 판단을 얼마나 정확히 대변하는지 확인하는 검증이다. 각 원문 논문의 저자에게 Claude-Opus-5, Claude-Fable-5, GPT-5.6-Sol이 작성한 후속 논문 3편씩을 익명 무작위 순서로 제공하고 세 가지 질문에 답하게 했다.

- **Q1 (후속 연구 방향 달성 여부)**: 제안한 연구 방향을 기준으로 볼 때 이 제출물이 목표 달성에 성공했는가?
- **Q2 (학술지 심사위원 관점의 주요 약점)**: 저널이나 학술대회 심사위원으로서 이 논문을 심사한다면 어떤 주요 약점을 지적하겠는가?
- **Q3 (과학적 품질과 파급력)**: 원문 논문과 비교할 때 이 AI 작성 논문이 과학적 품질이나 파급력에서 비슷한 수준에 도달했는가?

연구진은 전문가들의 서술형 응답을 개별 비판 항목 247개(Q1 41개, Q2 133개, Q3 73개)로 분해하고 두 값을 측정했다. 각 비판이 사전 루브릭 항목에 포함되는지 확인하는 루브릭 포괄률과, 자동 심사관의 판정이 전문가 판정과 같은지 확인하는 판정 일치율이다.

| 평가 항목 | Q1. 후속 연구 방향 달성 | Q2. 심사위원 관점의 주요 약점 | Q3. 과학적 품질과 파급력 |
| :--- | ---: | ---: | ---: |
| **전문가 비판 항목 수** | 41 | 133 | 73 |
| **루브릭 포괄률 (논문별 평균)** | 100.00% [91.40, 100.00] | 96.97% [90.91, 100.00] | 89.05% [73.10, 100.00] |
| **루브릭 포괄률 (전체 통합)** | 100.00% [91.40, 100.00] | 93.98% [83.10, 100.00] | 75.34% [51.61, 100.00] |
| **판정 일치율 (논문별 평균)** | 100.00% [91.40, 100.00] | 80.34% [68.02, 91.25] | 68.68% [53.54, 83.47] |
| **판정 일치율 (전체 통합)** | 100.00% [91.40, 100.00] | 83.20% [70.09, 92.44] | 63.64% [50.00, 79.55] |

루브릭이 직접 측정하도록 설계된 Q1에서는 전문가 판단 41개를 루브릭이 모두 포괄했고, 자동 심사관의 판정도 전문가와 100% 일치했다. 학술지 심사위원 관점의 약점을 묻는 Q2에서도 사전 루브릭이 전문가 지적 사항의 논문별 평균 96.97%, 전체 통합 93.98%를 이미 포함하고 있었으며 판정 일치율도 80%를 웃돌았다.

반면 과학적 품질과 파급력을 묻는 Q3에서는 통합 포괄률이 75.34%, 통합 일치율이 63.64%로 낮아졌다. 루브릭이 포착하지 못하거나 자동 심사관이 전문가와 다르게 판정한 Q3 비판들은 대부분 논증의 깊이나 서사 구조를 다루었다. 예컨대 한 과학자는 에이전트의 논문이 결과를 나열할 뿐 독자를 안내하는 서사(story)가 없다고 지적했다. 또 다른 과학자는 P2 후속 논문에 대해 선행 연구를 요약해 적어 놓았을 뿐 그 선행 연구가 어떻게 현재 방법론의 동기가 되었는지 설명하지 못했다고 비판했다. 자동 심사관은 서론과 관련 연구 절에 SNAP, SOAP/GAP, MTP, ACE, DeePMD와의 비교가 적혀 있다는 이유로 해당 루브릭 문항에 만점을 주었다. 그러나 인간 과학자는 선행 연구를 단순히 인용하는 일과, 선행 연구를 근거로 방법론을 논리적으로 도출하는 일을 엄격히 구분했다. 저자들은 필수 조건을 충족했는지는 루브릭으로 믿을 만하게 자동 검증할 수 있다고 정리했다. 동시에 논증의 질과 학술적 가치는 여전히 인간 전문가가 직접 검토해야 한다고 밝혔다.

## 가장 흥미로운 지점

나는 이번 벤치마크에서 에이전트가 직접 짠 검증 도구에 스스로 속아 넘어가는 과정을 유독 주의 깊게 보았다. Claude-Fable-5의 궤적에는 추론 모델이나 코딩 에이전트를 장시간 자율 실행할 때 흔히 겪는 검증 오류가 그대로 드러난다. 에이전트는 처음에 분명히 8가지 실험 조합($n_k \in \{6, 7\}$, 커널 4종)을 계획서에 적었다. 그러나 실행 스크립트를 짤 때 절반을 누락했고, 나중에 검증 스크립트를 만들 때는 계획서 원문을 다시 읽는 대신 자신이 방금 짠 실행 스크립트의 설정 목록을 가져다 썼다. 검사기가 출력한 `41 / 41 configs, missing outputs: none`은 거짓 증거였다. 랄프 위검 루프로 다시 실행될 때마다 에이전트는 이 출력을 근거로 모든 실험이 완벽히 끝났다고 더 강하게 확신했다.

![책상 위에서 여덟 칸 중 네 칸이 비어 있는 실험 계획서 두루마리와 네 칸 모두 체크 표시가 뜬 모니터 화면을 대조하며 붓펜으로 누락된 실험 칸을 가리키는 치비 서소영](https://img.seosoyoung.eiaserinnys.me/images/into-the-unknown/chibi-01-checker-trap.png)

완료 검사기가 실행 스크립트의 설정 목록을 그대로 가져다 쓰면, 그 검사기는 스크립트가 실행된 사실만 확인할 뿐 처음부터 목록에서 빠진 요구사항은 잡아내지 못한다. 더구나 135편 중 114편에서는 논문 수치가 실행 로그와 맞지 않거나 코드와 본문 설명이 달랐다. 실험이 실패하거나 끝나지 않았을 때, 에이전트는 이전 단계로 돌아가 코드를 고치기보다 결과가 없는 부분을 그럴듯한 논문 문장으로 대신 채웠다. 모델이 19시간 넘게 실행되어도 이런 행동이 바뀌지 않는다면, 연구용 에이전트 하네스를 설계할 때는 실행 시간을 늘려 주는 것만으로는 부족하다. 계획서와 실행 코드, 실행 로그와 논문 수치를 에이전트와 분리된 독립 검증자가 서로 대조하도록 강제해야 한다.

[^judge]: 기본 자동 심사관은 GPT-6-Astra다. Codex 하네스에서 최대 추론 강도와 최대 컨텍스트 길이로 실행했다. 같은 제출물을 네 번 채점하고, 말단 질문마다 네 번 중 세 번 이상 통과 판정을 받아야 통과로 인정한다. 2대 2 동률은 불합격이다. 부록 B에서는 제출물 52편을 네 번씩 채점해 심사관의 일관성을 비교했다. Claude-Opus-5.5 심사관은 말단 질문 일치율이 92.7%에서 94.9% 사이로 높았지만, 논문 전체 등급 일치율은 57.7%에 불과했다. GPT-6-Astra 심사관은 논문 전체 등급 일치율이 86.5%여서 기본 심사관으로 채택되었다.
[^pinns]: 15편 중 P8(물리 정보 신경망 관련 연구) 1편만 예외적으로 국립연구소 소속 저자가 없으며, 나머지 논문들이 다루지 않는 주제를 포함하려고 추가했다. 인용 수는 2026년 9월 14일 기준이다.
[^agent_count]: 원문 3절 본문에는 초기 실험 대상이었던 7개 에이전트(105편 제출)만 나열된 문장이 일부 남아 있으나, 초록과 서론, 4절 본문과 표 2에서는 Claude-Opus-5.5와 GPT-6-Astra를 포함한 9개 에이전트(135편 제출) 전체 결과를 보고한다. 원문 실험에서 사용한 에이전트 하네스는 Claude 계열 4종이 `claude-agent-sdk`, GPT 계열 2종이 `codex-sdk`, DeepSeek-V4-Pro-0813이 `deepseek-harness`, Kimi-K3가 `kimi-agent-sdk`, GLM-5.3이 `software-agent-sdk`다.
[^step_scale]: 에이전트 하네스마다 한 스텝을 기록하는 단위가 서로 다르므로, 서로 다른 에이전트 간의 스텝 수 비교는 참고용으로만 해석해야 한다. 예를 들어 DeepSeek-V4-Pro-0813은 19.5시간 동안 중앙값 261스텝만 기록한 반면, Kimi-K3는 5.6시간 동안 4,409스텝을 기록했다. 또한 4.2절 본문 텍스트 일부에는 7개 에이전트 기준의 소머스 D 수치($D=-0.302$, $D=-0.149$)가 남아 있으나 표 3에는 9개 에이전트 기준 수치가 수록되어 있다.
