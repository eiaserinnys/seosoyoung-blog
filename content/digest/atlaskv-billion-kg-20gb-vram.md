## 3줄 요약

1. 홍콩과기대(HKUST)와 화웨이 공동 연구진이 파라메트릭 지식 증강 프레임워크 AtlasKV를 발표했다. 외부 검색기나 긴 프롬프트 문맥, 재학습 없이 10억 트리플 규모의 지식 그래프를 대규모 언어 모델(LLM)의 셀프 어텐션 층에 통합하며, 필요한 GPU VRAM은 20GB 미만이다.
2. KG2KV 파이프라인은 지식 그래프의 `(주어, 관계, 목적어)` 트리플을 어텐션의 쿼리-키-값(Q-K-V) 구조로 바꿔, 학습 데이터의 질문 속성 다양성을 기존 합성 방식의 0.003%에서 7.864%로 높였다. 3계층 군집 기반 가지치기 알고리즘 HiKVP는 추론할 때의 시간 복잡도와 메모리 복잡도를 지식 베이스 크기 $M$의 세제곱근 수준인 $\mathcal{O}(\sqrt[3]{M})$으로 낮췄다.
3. LLaMA3.1-8B-Instruct 백본 실험에서 기존 파라메트릭 기법인 KBLaM은 10만 트리플을 처리하는 데 40GB 이상의 VRAM을 소비했지만, AtlasKV는 10억 트리플에서도 20GB 미만의 VRAM만 썼다. 또한 AtlasKV는 3,000스텝만 학습하고도 학습에 쓰지 않은 분포 외(OOD) 데이터셋 3종 모두에서 2만 스텝을 학습한 KBLaM보다 높은 지식 접지 정확도와 답변 관련성 점수(HiKVP 미적용 변형 기준)를 기록했다.

## 기존 지식 증강 패러다임의 두 가지 병목

대규모 언어 모델이 외부 지식을 활용하는 방식은 지식을 프롬프트 문맥으로 건네는 비파라메트릭(non-parametric) 접근과 모델 내부의 연산 파라미터나 키-값 표현으로 통합하는 파라메트릭(parametric) 접근이 있다. 가장 널리 쓰이는 비파라메트릭 방식인 검색 증강 생성(RAG)은 외부 지식 베이스나 지식 그래프에서 질문과 관련된 텍스트 조각 또는 부분 그래프를 검색해 프롬프트 문맥으로 제공한다. 모델 가중치를 그대로 둔 채 외부 지식을 참조할 수 있지만, 전체 응답 품질이 외부 검색기의 정확도에 좌우되고 지식 규모가 커질수록 최근접 이웃 탐색과 긴 문맥 처리에 드는 추론 지연 시간과 메모리 사용량이 급증한다.

이와 달리 파라메트릭 방식은 외부 지식을 모델 내부 연산에 직접 통합하므로 별도의 검색기나 긴 프롬프트 문맥을 요구하지 않는다. LoRA나 어댑터(adapter) 같은 초기 파라메트릭 기법은 새로운 지식 분포가 추가될 때마다 모델을 다시 학습해야 했다. 이를 해결하기 위해 제안된 KBLaM[^1]은 '직사각형 어텐션(Rectangular Attention)'을 도입했다. 이 방식에서는 외부 지식 항목을 문장 인코더로 고정 길이의 키-값(Key-Value) 임베딩 쌍으로 바꾼 뒤, 학습 가능한 선형 투영 헤드를 거쳐 LLM의 셀프 어텐션 층에 주입한다. 투영 헤드를 한 번 학습해 두면 새 지식 베이스가 생겨도 재학습 없이 키-값 임베딩만 교체하거나 추가할 수 있다.

[^1]: Wang 외 (2024), 「KBLaM: Knowledge Base augmented Language Model」. 입력 시퀀스 길이를 $N$, 외부 지식 항목 수를 $M$이라 하면, 쿼리 토큰 $N$개가 문맥 토큰 $N$개와 외부 지식 키-값 쌍 $M$개 모두에 동시에 어텐션을 계산한다. 따라서 어텐션 행렬은 $N \times (M+N)$ 크기의 직사각형이 된다.

| 지식 증강 패러다임 | 대표 기법 | 외부 검색기 및 긴 문맥 의존 | 새 지식 추가 시 모델 재학습 | 대규모 지식 그래프 확장성 |
| --- | --- | --- | --- | --- |
| 비파라메트릭 (Non-parametric) | RAG, GraphRAG | 의존함 (지연 시간 증가) | 불필요 | 검색 및 문맥 길이 병목 발생 |
| 기존 파라메트릭 (Traditional Parametric) | LoRA, Adapter | 불필요 | 필요함 (적응 비용 높음) | 재학습 비용으로 확장 제한 |
| 키-값 주입형 파라메트릭 | KBLaM | 불필요 | 불필요 (재학습 없는 적응) | 선형 복잡도 $\mathcal{O}(M)$으로 10만 트리플에서 40GB 초과 |
| 계층적 키-값 주입형 파라메트릭 | AtlasKV | 불필요 | 불필요 (재학습 없는 적응) | 세제곱근 복잡도 $\mathcal{O}(\sqrt[3]{M})$으로 10억 트리플에서 20GB 미만 |

그러나 KBLaM이 제시한 키-값 주입형 파라메트릭 패러다임도 수억 개 규모의 지식 그래프로 확장할 때는 학습 데이터 품질과 메모리 복잡도에서 두 가지 한계를 드러낸다.

첫 번째 한계는 어텐션 투영 헤드를 학습시킬 고품질 Q-K-V 데이터를 확보하기 어렵다는 점이다. 기존 KBLaM은 비정형 문서에서 사람이 미리 정의한 고정 스키마(`description`, `objectives`, `purpose` 등)에 맞춰 LLM으로 쿼리(Q), 키(K), 값(V) 문장 묶음을 합성했다. 이 방식은 질문 속성(enquiry attribute)의 다양성이 극도로 제한된다. 이 때문에 학습 단계에서 보지 못한 질문 유형이 나오는 분포 외(OOD, Out-of-Distribution) 환경에서는 일반화 성능이 급격히 떨어진다.

두 번째 한계는 지식 그래프의 트리플 수가 수천만 개 이상으로 늘어날 때 발생하는 연산량과 메모리 부담이다. 직사각형 어텐션의 시간 복잡도 $\mathcal{O}((M+N) \cdot N \cdot D)$와 메모리 복잡도 $\mathcal{O}((M+N) \cdot (N+D))$는 지식 항목 수 $M$에 비례해 선형으로 증가한다. 전통적인 셀프 어텐션의 이차 복잡도보다는 효율적이지만, 지식 그래프 규모가 수천만에서 수십억 트리플로 커지면 선형 복잡도조차 감당하기 어렵다. 실제로 KBLaM은 10만 개의 트리플만 통합해도 추론할 때 40GB 이상의 GPU VRAM을 요구한다.

## 방법론 1: 지식 그래프 트리플을 Q-K-V로 변환하는 KG2KV

![KG2KV 파이프라인이 지식 그래프 트리플에서 목적어 또는 주어를 마스킹해 Q-K-V 문장으로 변환하는 과정](https://img.seosoyoung.eiaserinnys.me/images/atlaskv-billion-kg-20gb-vram/fig2-kg2kv.png)
*그림 2: 지식 그래프 트리플을 Q-K-V 데이터로 변환하는 KG2KV 예시. 목적어를 마스킹할 때와 주어를 마스킹할 때 관계어가 서로 다른 속성 명사로 재작성된다. (출처: arXiv:2510.17934)*

첫 번째 병목인 학습 데이터 품질과 일반화 문제를 해결하기 위해, 연구진은 지식 그래프의 기본 단위인 트리플 $(h, r, t)$가 셀프 어텐션의 쿼리-키-값 구조와 형태적으로 대응한다는 점에 주목했다. 이를 바탕으로 지식 그래프 트리플을 Q-K-V 문자열과 문장 임베딩으로 변환하는 KG2KV 파이프라인을 설계했다.

KG2KV는 개별 트리플 $(h, r, t)$에서 마스킹할 개체를 고르고, 관계어를 명사로 바꾼 뒤, 질문 접두사를 붙이는 순서로 Q-K-V 문장을 만든다. 먼저 트리플 $(h, r, t)$에서 주어 개체($h$)와 목적어 개체($t$) 중 하나를 마스킹하고, 마스킹된 개체를 어텐션이 찾아내야 할 값(Value)으로 지정한다. 그다음 마스킹되지 않은 나머지 개체와 관계($r$)를 결합해 키(Key) 문자열을 만든다. 이때 마스킹된 개체가 주어인지 목적어인지에 따라 관계 동사나 접속사를 속성을 나타내는 자연스러운 명사로 재작성한다.

예를 들어 그림 2의 `(John founded StockLemon.com, because, John has made profits every year since he started short selling)` 트리플에서 목적어($t$)를 마스킹하면, 값(V)은 `"John has made profits every year since he started short selling"`이 된다. 이때 목적어는 이유에 해당하므로 LLM(GPT-4o-mini)이 관계어 `because`를 명사 `cause`로 재작성하고, 키(K) 문자열은 `"the cause of John founded StockLemon.com"`이 된다. 반대로 주어($h$)를 마스킹하면 이번에는 마스킹된 개체가 결과에 해당하므로, 관계어 `because`는 반대 방향의 명사 `result`로 재작성되고 키(K) 문자열은 `"the result of John has made profits ..."`가 된다.

마지막으로 키 문자열 앞에 `"What is ..."`, `"Tell me ..."`, `"Provide details on ..."` 등 다양한 질문 접두사를 무작위로 붙여 학습용 쿼리(Q) 문장을 완성한다. 완성된 키와 값 문자열은 오프라인에서 문장 인코더를 거쳐 기본 임베딩 벡터 $\bm{k}^m, \bm{v}^m$으로 변환되어 디스크에 저장된다.

| 데이터 구축 방식 | 질문 속성 다양성 비율 ($\uparrow$) | 트리플당 평균 토큰 비용 ($\downarrow$) |
| --- | --- | --- |
| 기존 합성 방식 (Synthetic) | 0.003% | 349.9 |
| KG2KV | 7.864% | 165.7 |

논문의 표 1(위 표)에서 보듯 KG2KV는 질문 속성 다양성과 토큰 효율 양쪽에서 기존 합성 방식보다 훨씬 우수하다. 질문 속성 다양성 비율(전체 트리플 수 대비 고유 질문 속성 수)은 기존 합성 방식이 0.003%에 그친 반면, 지식 그래프의 다양한 실제 관계를 그대로 활용하는 KG2KV는 7.864%로 약 2,600배 높다. 또한 관계어를 명사로 바꿀 때 LLM 프롬프트에는 트리플 전체 문장을 넣지 않고 '관계 구문'과 '마스킹된 개체가 주어인지 목적어인지'만 넣는다. 덕분에 트리플당 평균 토큰 소비량이 349.9토큰에서 165.7토큰으로 52.6% 줄어든다[^2].

[^2]: 부록 B.2의 민감도 실험에서 LLM을 호출하는 관계어 재작성을 생략한 변형 모델(`AtlasKV-Ntrain`, `AtlasKV-Ntest`)은 원본 관계어와 개체 문자열을 단순 결합해 키를 만든다. 이 모델도 정확도가 소폭 낮아졌을 뿐 KBLaM보다 훨씬 높은 접지 정확도를 유지한다. 초대규모 지식 그래프를 구축할 때 토큰 비용과 정확도 요구 수준에 따라 재작성 여부를 선택할 수 있다.

## 방법론 2: 3계층 키-값 가지치기 알고리즘 HiKVP

두 번째 병목인 추론할 때의 메모리와 연산 복잡도를 줄이기 위해 제안된 것이 계층적 키-값 가지치기(HiKVP, Hierarchical Key-Value Pruning) 알고리즘이다. 질의 하나에 답하는 데 실제로 쓰이는 외부 지식은 전체 지식 그래프의 극히 일부뿐이며, 질문과 무관한 대량의 지식을 어텐션 층에 한꺼번에 주입하면 응답 정확도를 떨어뜨리는 노이즈로 작용한다. HiKVP는 바로 이 점에 착안해, 질의와 관련이 높은 소수의 키-값 쌍만 계층적으로 추려 어텐션에 참여시킨다.

먼저 오프라인 전처리 단계에서 전체 $M$개의 지식 키 임베딩을 UMAP으로 차원을 줄인 뒤, 가우시안 혼합 모델(GMM)로 군집화해 3계층(루트 계층 $R$, 중간 계층 $I$, 말단 계층 $L$) 트리 구조를 만든다. 각 계층이 연산과 메모리 부담을 균등하게 분담하도록 모든 군집 크기를 $S = \lceil \sqrt[3]{M} \rceil$로 맞춘다. 그러면 말단 키는 $M_L = M$개, 중간 키는 $M_I = \lceil M^{2/3} \rceil$개, 루트 키는 $M_R \approx \lceil M^{1/3} \rceil$개가 된다. 상위 계층의 키 벡터는 하위 계층의 키 벡터를 풀링(pooling)해서 만든다.

| HiKVP 계층 | 전체 키 개수 | 단계별 GPU 적재 키 개수 | Top-$k$ 기본값 | 연산 후 메모리 관리 |
| --- | --- | --- | --- | --- |
| 루트 계층 ($R$) | $\lceil M^{1/3} \rceil$ | $\lceil M^{1/3} \rceil$ | $128$ | 하위 군집 매핑 후 CPU 메모리로 반환 |
| 중간 계층 ($I$) | $\lceil M^{2/3} \rceil$ | $128 \lceil M^{1/3} \rceil$ | $64$ | 하위 군집 매핑 후 CPU 메모리로 반환 |
| 말단 계층 ($L$) | $M$ | $64 \lceil M^{1/3} \rceil$ | $16$ | 최종 $k_L$개 값 벡터만 GPU에 적재해 어텐션 결합 |

추론할 때는 전체 계층의 키와 값 벡터를 CPU 메인 메모리에 보관하고, 아래 3단계에 걸쳐 필요한 후보만 GPU VRAM으로 호출한다.

1. 루트 계층 가지치기: 초기에는 루트 계층의 투영된 키 벡터 $\tilde{\mathbf{k}}_R^{(l)}$(약 $\sqrt[3]{M}$개)만 GPU 메모리에 적재한다. 현재 토큰의 쿼리 벡터 $\tilde{\mathbf{q}}_n^{(l)}$과 루트 키 사이의 내적 어텐션 점수 $\text{logits}_{kg_R} = \langle \tilde{\mathbf{q}}_n^{(l)}, \tilde{\mathbf{k}}_R^{(l)} \rangle / \sqrt{D}$를 계산해 소프트맥스를 적용한 뒤, 점수가 높은 상위 $k_R$개(기본값 128)의 루트 키를 선택한다. 선택된 루트 키와 연결된 중간 계층 키 인덱스($k_R \cdot S$개)를 매핑한 직후 루트 키는 다시 CPU 메모리로 내린다.
2. 중간 계층 가지치기: 매핑된 $k_R \cdot S$개의 중간 계층 키 $\bar{\tilde{\mathbf{k}}}_I^{(l)}$만 CPU에서 GPU 메모리로 올린다. 같은 방식으로 쿼리와의 어텐션 점수를 계산해 상위 $k_I$개(기본값 64)의 중간 키를 추려내고, 이에 연결된 말단 계층 키 인덱스($k_I \cdot S$개)를 확보한 뒤 중간 키를 CPU 메모리로 내린다.
3. 말단 계층 선택 및 어텐션 결합: 마지막으로 $k_I \cdot S$개의 말단 키 $\bar{\tilde{\mathbf{k}}}_L^{(l)}$을 GPU로 올려 어텐션 점수를 계산하고, 상위 $k_L$개(기본값 16)의 최종 말단 키 로짓 $\overline{\text{logits}}_{kg}$를 선택한다. 그다음 이 $k_L$개 인덱스에 대응하는 값 벡터 $\bar{\tilde{\mathbf{v}}}^{(l)} \in \mathbb{R}^{k_L \times D}$만 GPU로 가져온다. 이를 기존 문맥 시퀀스의 어텐션 출력과 동적 가중치($\bar{\lambda}_{kg}, \lambda_{seq}$)로 합산한다.

![3계층 지식 키 구조와 CPU-GPU 메모리 간 계층적 키-값 가지치기(HiKVP) 추론 파이프라인](https://img.seosoyoung.eiaserinnys.me/images/atlaskv-billion-kg-20gb-vram/fig3-hikvp-overview.png)
*그림 3: $l$번째 어텐션 층에서 3계층 지식 키(루트, 중간, 말단)를 사용하는 계층적 키-값 가지치기(HiKVP) 개요. 회색 배경으로 표시한 부분만 GPU VRAM에 적재되어 연산된다. (출처: arXiv:2510.17934)*

$$
\tilde{\mathbf{y}}_n^{(l)} = \bar{\lambda}_{kg} \cdot \text{Softmax}(\overline{\text{logits}}_{kg}) \cdot \bar{\tilde{\mathbf{v}}}^{(l)} + \lambda_{seq} \cdot \text{Softmax}(\text{logits}_{seq}) \cdot \mathbf{v}^{(l)}
$$

이 과정에서 학습 가능한 파라미터는 지식 그래프 전용 쿼리 헤드 $\tilde{\mathbf{W}}_Q$와 키-값 투영 헤드 $\tilde{\mathbf{W}}_K, \tilde{\mathbf{W}}_V$뿐이며, 백본 LLM의 기존 가중치는 동결된다[^3].

[^3]: 학습 단계에서는 HiKVP 가지치기를 적용하지 않는다. 연구진은 14억 9,200만 트리플 규모의 ATLAS-Wiki에서 단 2만 개의 트리플만 표본으로 추출해 투영 헤드를 3,000스텝 동안 학습시켰다. 배치 크기는 10이고, 100스텝마다 지식 그래프 크기를 4씩 늘려 최대 120개 트리플까지만 학습했다. 이렇게 소규모로 학습했는데도 수만에서 수십억 트리플까지 일반화되는 것을 확인했다.

| 방법론 | 추론 시간 복잡도 | 추론 메모리 복잡도 |
| --- | --- | --- |
| ICL | $\mathcal{O}((MT + N)^2 \cdot D)$ | $\mathcal{O}((MT + N) \cdot (MT + N + D))$ |
| RAG | $\mathcal{O}(M + RT + (RT + N)^2 \cdot D)$ | $\mathcal{O}((RT + N) \cdot (RT + N + D))$ |
| CAG | $\mathcal{O}((RT + N)^2 \cdot D)$ | $\mathcal{O}((RT + N) \cdot (N + D))$ |
| KBLaM | $\mathcal{O}((M + N) \cdot N \cdot D)$ | $\mathcal{O}((M + N) \cdot (N + D))$ |
| AtlasKV | $\mathcal{O}((C_t \sqrt[3]{M} + N) \cdot N \cdot D)$ | $\mathcal{O}((C_m \sqrt[3]{M} + N) \cdot (N + D))$ |

논문의 표 2(위 표)는 문맥 내 학습(ICL), RAG, 캐시 증강 생성(CAG), KBLaM, AtlasKV의 시간 및 메모리 복잡도를 비교한다($T$는 트리플당 평균 토큰 길이, $R$은 검색된 관련 트리플 수). HiKVP를 적용한 AtlasKV는 세 단계에서 각각 $\sqrt[3]{M}$개, $k_R \sqrt[3]{M}$개, $k_I \sqrt[3]{M}$개의 키만 GPU에 적재한다. 따라서 상수 $C_t = 1 + k_R + k_I$와 $C_m = \max(1, k_R, k_I)$를 두면 시간 복잡도와 메모리 복잡도가 모두 $\sqrt[3]{M}$에 비례하는 부분선형(sub-linear)으로 낮아진다. 트리플이 10억($10^9$) 개로 늘어도 군집 크기는 세제곱근인 $\sqrt[3]{10^9} = 1{,}000$이므로, GPU VRAM 소비량이 급증하지 않는다.

## 실험 결과: 10억 트리플까지의 메모리 효율과 OOD 일반화 성능

모든 학습과 평가 실험은 단일 48GB GPU(bfloat16 정밀도) 환경에서 LLaMA3.1-8B-Instruct를 백본 모델로 삼아 진행됐다. 32개 어텐션 층 가운데 3개 층마다($K=3$) 지식을 주입했다[^4]. 문장 인코더로는 경량 오픈소스 모델인 `all-MiniLM-L6-v2`($D_E=384$)와 상용 API 모델인 `text-embedding-3-large`($D_E=3072$)를 함께 검증했다. 평가에는 학습 데이터(ATLAS-Wiki-QKV)와 분포가 다른 세 가지 분포 외(OOD) 데이터셋, 곧 Enron, ATLAS-Pes2o-QKV(학술 논문 기반 지식 그래프), ATLAS-CC-QKV(Common Crawl 기반 지식 그래프)를 썼다.

[^4]: 부록 B.3의 주입 주기 실험($K \in \{1, 3, 10\}$)에서는 모든 층에 주입하면($K=1$) 초기 어텐션 층에 노이즈가 유입되어 정확도가 떨어졌고, 10개 층마다 주입하면($K=10$) 지식 주입량이 부족해 정확도가 낮아졌다. 3개 층마다 주입하는 $K=3$이 모든 지식 그래프 크기에서 접지 정확도가 가장 높았다.

## 가장 흥미로운 지점

Enron 평가 데이터셋에서 나타난 성능 역전은 데이터 다양성이 모델의 검색 메커니즘 학습에 미치는 영향을 잘 보여준다. Enron 평가 데이터셋은 KBLaM 연구진이 만든 벤치마크로, 자체 합성 학습 데이터와 같은 질문 속성(`description`, `objectives`, `purpose` 등)을 썼다. 즉 질문 속성의 분포로 보면 KBLaM에게는 분포 내(In-Distribution) 조건에 가깝다. 이에 비해 위키피디아 지식 그래프에서 추출한 ATLAS-Wiki-QKV로 학습한 AtlasKV에게는 공통된 질문 속성이 거의 없어 불리하다.

그럼에도 표 3과 그림 5의 AtlasKV는 약 7분의 1의 학습 스텝(3,000스텝 대 2만 스텝)만으로 Enron의 모든 트리플 규모($10^2$부터 $10^4$까지)에서 KBLaM보다 높은 지식 접지 정확도와 GPTScore를 기록했다. 부록 E의 학습 역학 실험(정답 키-값 쌍과 무작위 키-값 쌍의 손실 곡선 비교)이 그 이유를 뒷받침한다. 질문 속성 다양성이 7.864%에 달하는 KG2KV 데이터로 학습하면, 투영 헤드는 특정 스텝 이후 고정된 질문 표현을 암기하는 대신 외부 키 임베딩 공간에서 의미를 대조해 검색하는 일반화된 어텐션 연산을 학습한다는 것이다.

| 방법론 | $10^1$ | $10^2$ | $10^3$ | $10^4$ |
| --- | --- | --- | --- | --- |
| AtlasKV (HiKVP 적용, 128-64-16) | 4.10초 | 4.02초 | 4.44초 | 6.21초 |
| AtlasKV (HiKVP 미적용) | 1.00초 | 1.98초 | 2.11초 | 2.09초 |
| CPU-GPU 전송으로 인한 추가 지연 | +3.10초 | +2.04초 | +2.33초 | +4.12초 |

부록 F.2와 부록 J는 VRAM 절감의 이면에 존재하는 두 가지 구조적 제약을 구체적인 수치로 밝힌다. HiKVP는 이론적 시간 복잡도를 $\mathcal{O}(\sqrt[3]{M})$으로 낮추고 GPU VRAM 사용량을 20GB 미만으로 억제한다. 대신 어텐션 주입 층마다 루트, 중간, 말단 계층의 키와 값을 CPU 메모리와 GPU VRAM 사이에서 올리고 내려야 하므로 I/O 비용이 든다. 위 표(논문의 표 11)에서 $10^4$ 트리플 기준 평균 추론 시간은 HiKVP를 적용하지 않으면 2.09초였고, 적용하면 CPU-GPU 데이터 전송 지연 4.12초가 더해져 6.21초가 걸렸다.

또한 KG2KV는 지식 그래프의 각 트리플을 독립된 키-값 쌍으로 변환해 그래프의 연결 구조를 평탄화(flattening)하므로, 여러 엣지를 순차적으로 따라가야 하는 다중 홉(multi-hop) 추론에는 직접 대응하지 못한다. 즉 AtlasKV가 20GB 미만의 VRAM에서 10억 개 트리플을 처리할 수 있었던 것은 GPU 메모리에 집중되던 저장 부담을 CPU 메인 메모리와 PCIe 전송 대역폭으로 분담시켰기 때문이며, 저자들은 향후 과제로 CPU-GPU 전송 지연을 줄이는 시스템 스케줄링 알고리즘과 계층별 다중 헤드 학습을 제시하고 있다.
